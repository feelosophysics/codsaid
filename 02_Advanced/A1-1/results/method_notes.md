# A1-1 분석 방법·한계·확장 설계

현재 구현의 선택 이유와 해석 한계, 규모 확장 및 머신러닝 후속 설계를 설명한다. 기본 분석은 고정 난수로 만든 합성 거래·상품·이미지를 사용한다. 아래 대규모 처리와 예측 모델은 설계 제안이며 구현·성능 실험 결과가 아니다. 실제 실행 결과는 [분석 요약](analysis_summary.md), 실행 시각·셀별 결과는 [노트북 실행 기록](notebook_execution.md)에서 확인한다.

## 1. IQR과 정규분포 기반 방법의 차이

현재 `src/pipeline.py`의 `iqr_bounds()`는 `IQR = Q3 − Q1`과 경계 `Q1 − 1.5×IQR`, `Q3 + 1.5×IQR`을 계산한다. `detect_outliers()`는 경계 밖에 표시를 붙이고, `treat_outliers()`는 비교용 클리핑 또는 제외 Series를 반환한다. 원본 거래와 RFM 금액은 유지한다.

| 비교 | IQR 방식 | 평균·표준편차 기반 z-score 방식 |
| --- | --- | --- |
| 기준 | 가운데 50%의 범위인 사분위수 | `z = (x − 평균) / 표준편차` |
| 흔한 규칙 | Q1·Q3에서 각각 1.5×IQR 바깥 | 예: `abs(z) > 3` |
| 극단값의 영향 | 평균·표준편차보다 극단값에 덜 민감 | 극단값이 평균과 표준편차를 바꿔 다른 극단값을 가릴 수 있음 |
| 분포 가정 | 정규분포를 가정하지 않고 후보를 표시 | z-score 계산 자체는 정규분포를 요구하지 않지만, ‘3σ 밖은 매우 드물다’는 확률 해석은 정규분포에 의존 |
| 사용 판단 | 치우침·극단값이 있는 분포의 초기 탐색에 유용 | 대체로 대칭이고 정규분포에 가까운 연속형 값에서 기준 해석이 쉬움 |

정규분포에 가깝더라도 두 규칙이 같은 후보를 고르는 것은 아니다. IQR 경계는 정규분포에서 대략 평균 ±2.70σ에 해당하므로 ±3σ 규칙과 다르다.

**IQR도 비대칭 분포의 문제를 자동 해결하지 않는다.** 가격·구매 금액처럼 오른쪽 꼬리가 긴 분포에서는 정상 고가 거래가 많이 표시될 수 있다. 여러 상품군을 합친 분포의 한 경계로 비교하면 가격대가 다른 카테고리를 오류로 오해할 수 있으며, IQR=0인 이산형·동점이 많은 데이터에서는 작은 차이도 후보로 잡힌다. 히스토그램·카테고리·기록 원본을 함께 확인하고 필요하면 그룹별 경계, 양수 값의 로그 변환 후 탐색, 업무상 허용 범위를 비교한다. 후보라는 이유만으로 삭제하지 않는다.

기본 실행의 배송 일수 경계는 −1.5–10.5일, 후보는 15행이다. 음수 하한은 통계 규칙의 결과이며 음수 배송 일수가 업무적으로 유효하다는 뜻은 아니다. [전후 박스플롯](figures/02_boxplot.png)의 클리핑은 분포 비교용이다. 실제 장기 배송의 오류 여부는 배송 이력으로 확인해야 한다.

## 2. 그룹별 결측치 대치의 통계적 위험

`DataAnalyzer.handle_missing_values()`는 상품 가격·평점을 상품 단위로, 배송 일수를 거래 행 단위로 카테고리별 중앙값에 대치한다. 그룹 전체가 비면 전체 중앙값을 쓰고 컬럼 전체가 비면 오류를 낸다. 고객 ID·구매일·거래 금액은 추정하지 않는다. `handle_missing()`는 같은 인자를 이 메서드에 전달하는 호환 이름이다.

카테고리를 쓰는 이유는 서로 다른 상품군에 하나의 대표값을 적용하는 문제를 줄이기 위해서다. 상품 속성은 거래 표에서 대치 통계를 계산하면 많이 팔린 상품에 가중치가 붙으므로 상품 표에서 계산한다. 하지만 그룹별 대치도 관측값을 복원하는 것은 아니다.

- **그룹 안의 분산 축소**: 여러 결측치를 동일한 중앙값으로 채우면 값이 중앙에 몰린다. 중앙값 대치에서 분산이 언제나 줄어든다고 단정할 수는 없지만, 실제로 존재할 변동을 표현하지 못하고 분포·상관·표준오차를 왜곡할 수 있다. 특히 평균 대치는 관측값 주위의 변동을 축소한다.
- **그룹 간 차이 왜곡**: 카테고리별로 서로 다른 대표값을 반복 주입하면 그룹의 전형적인 값이 과하게 강조될 수 있다. 그룹 간 차이가 항상 커지는 것은 아니며, 결측 비율과 실제 누락 값에 따라 커지거나 작아질 수 있다.
- **결측 원인과 작은 그룹**: 높은 가격이나 낮은 평점에서 누락이 더 자주 발생한다면 관측값의 중앙값은 누락된 값의 좋은 추정이 아닐 수 있다. 관측값이 적은 그룹의 중앙값도 불안정하며, 전체 중앙값 fallback은 상품군 차이를 반영하지 못한다.

현재 audit에는 상품별 가격 12개·평점 7개, 거래 배송 일수 272개의 대치 수가 남는다. 실제 데이터에서는 대치 전 결측 여부 플래그와 그룹별 관측 수·결측 비율을 보존하고, 원래 관측값과 대치 후 값의 중앙값·분산·분포를 나란히 보고한다. 중앙값·평균·전체 대표값 등 대안에 따른 결론 변화를 비교하고 원본 자료로 누락 원인을 확인한다. 데이터가 충분하면 작은 그룹을 전체 분포 쪽으로 완화하는 계층적 추정이나 불확실성을 반영하는 다중 대치를 후속 분석에서 검토할 수 있다. 현재 미션에 이 모델들을 추가 구현하지는 않았다.

예측 모델로 확장할 경우 대치 통계는 학습 구간에서만 구한 뒤 검증·테스트에 적용한다. 미래 기간을 포함해 중앙값을 계산하면 정보 누수가 생긴다.

## 3. NumPy 벡터 연산이 유리한 이유

`engineer_features()`는 아래처럼 상품 축을 유지하고 높이·너비·채널 축을 한 번에 줄인다.

```python
axes = tuple(range(1, self.images.ndim))
image_mean = self.images.mean(axis=axes, dtype=np.float64)
image_std = self.images.std(axis=axes, dtype=np.float64)
```

Python에서 이미지·픽셀마다 값을 꺼내 연산하면 각 반복에 인터프리터와 객체 처리 비용이 든다. NumPy에서는 고정된 자료형의 배열을 내부 컴파일된 루프로 처리하므로 이 반복 비용을 줄인다. 내부 루프가 없어지는 것은 아니며, 모든 픽셀을 읽는 계산량은 여전히 이미지 수×높이×너비×채널 수에 비례한다. 같은 상품의 통계를 거래마다 다시 계산하지 않고 상품별로 한 번 계산해 `image_index`로 연결하는 것도 중복 작업을 줄인다.

**연속 메모리와 strides**: ndarray는 자료형·shape·각 축의 이동 바이트 수인 strides로 메모리의 값을 해석한다. C-contiguous 배열에서는 마지막 축의 이웃 값이 이어져 있어 순차 접근과 캐시 활용에 유리하다. 전치나 간격을 둔 슬라이싱은 비연속 view를 만들 수 있으며 올바른 계산은 가능하지만 접근 비용이 달라질 수 있다. `images.flags.c_contiguous`와 `images.strides`로 확인한다. `np.ascontiguousarray()`는 필요할 때만 사용한다. 비연속 배열을 연속 배열로 바꾸는 복사 자체가 시간과 메모리를 쓴다. [NumPy ndarray 공식 설명](https://numpy.org/doc/stable/reference/arrays.ndarray.html).

**SIMD와 CPU 벡터 연산**: CPU의 SIMD는 하나의 명령으로 여러 수치를 처리한다. NumPy는 일부 연산에서 CPU 기능에 맞는 구현을 선택해 이점을 얻는다. 지원 여부와 효과는 CPU, NumPy 빌드, 연산, dtype, strides 등에 따라 달라진다. 이 프로젝트에서 mean/std의 SIMD 경로를 측정하거나 모든 연산의 SIMD 사용을 입증한 것은 아니다. SIMD는 한 코어 안에서 여러 값을 처리하는 기능이며 여러 코어를 쓰는 멀티프로세싱과 구분한다. [NumPy CPU/SIMD 공식 설명](https://numpy.org/doc/stable/reference/simd/index.html).

데이터 생성의 브로드캐스팅은 작은 배열을 실제로 매번 복사하지 않고 축을 맞춰 연산할 수 있게 한다. 다만 연산 결과나 임시 배열은 크게 만들어질 수 있어 메모리 사용량을 고려해야 한다. [NumPy 브로드캐스팅 공식 설명](https://numpy.org/doc/stable/user/basics.broadcasting.html).

기본 이미지 픽셀 범위는 0–255이며 `image_mean`은 같은 스케일의 평균, `image_std`는 같은 단위의 모집단 표준편차(`ddof=0`)다. 두 값은 시각적 품질이나 상품 의미를 나타내지 않는다.

## 4. 이미지가 많아졌을 때의 병목과 대응

현재 입력은 `(80,16,16,3)`의 uint8 배열이어서 작다. 예를 들어 이미지 10만 개를 `(256,256,3)`으로 저장하면 원본 픽셀만 약 19.66GB(18.31GiB)다. 같은 크기의 float64 중간 배열 하나는 약 157.29GB(146.48GiB)이므로 원본 파일 크기만 보고 필요한 RAM을 판단하면 안 된다. `std(dtype=np.float64)`는 정밀도를 높이지만 편차 등의 계산에서 큰 중간 배열을 사용할 수 있다. [NumPy std의 계산 설명](https://numpy.org/doc/stable/reference/generated/numpy.std.html).

| 예상 병목 | 대응 설계 | 선택 시 주의할 점 |
| --- | --- | --- |
| 파일 읽기·사진 디코딩 | 변환한 `.npy` 피처 입력을 재사용하고 저장 장치 읽기 시간을 먼저 측정 | 배열 통계만 병렬화해도 디스크 병목은 해결되지 않음 |
| 배치 전체 적재와 float64 중간 배열 | `.npy`를 `np.load(..., mmap_mode="r", allow_pickle=False)`로 열고 상품 묶음별 mean/std 계산 | mmap만 적용해도 전체 배열에 std를 호출하면 큰 임시 배열이 생길 수 있으므로 묶음 처리도 필요 |
| 동일 이미지의 중복 처리 | 상품 ID·이미지 해시별 피처를 저장하고 변경된 상품만 다시 계산 | 이미지·계산 설정이 바뀌면 캐시를 갱신 |
| 너무 큰 픽셀 수 | 통일된 규칙으로 다운샘플링한 뒤 피처 계산 | 작은 무늬·엣지가 사라질 수 있어 원본과 비교하고 해상도를 기록 |
| CPU 계산 | 충분한 RAM과 독립적인 묶음이 있을 때 제한된 worker로 병렬 처리 | 프로세스마다 전체 배열을 복사하지 않고 파일 경로와 범위를 전달; 디스크·메모리 대역폭 경쟁 및 스레드 과다 생성 점검 |
| 탐색·시각화 비용 | 카테고리·기간을 고려한 층화 표본으로 탐색하고 seed·표본 수 기록 | 표본 통계와 전체 모집단 통계를 구분; 일부 상품만 처리하면 거래 피처 누락이 생김 |

묶음 처리에서는 예를 들어 상품 256개씩 읽어 각 묶음 안의 이미지 축을 벡터 연산하고, 작은 결과 벡터만 저장한다. 묶음을 순회하는 루프는 이미지·픽셀을 하나씩 처리하는 Python 루프와 다르다. 결과를 원래 `image_index` 순서로 결합하면 상품별 mean/std는 전체 배치 계산과 대조할 수 있다. 적절한 묶음 크기는 사용 가능한 메모리와 dtype·해상도로 정하고 실제로 측정해야 한다.

현재 `load_data()`는 전체 배열을 메모리에 올리므로 mmap·묶음 처리는 후속 설계다. 현재 구현이 위 규모를 처리한다고 주장하지 않는다. 먼저 I/O·피처 계산·조인·차트별 시간과 최대 메모리를 측정하고 확인된 병목에 맞춰 개선한다.

## 5. 머신러닝 확장: 향후 30일 재구매 예측

**예측 단위는 고객 한 명·기준 시점 T 한 개다.** T까지의 이력으로 다음 30일 `(T,T+30일]`에 유효한 양수 구매가 한 번 이상 있으면 `y=1`, 완전히 관측했지만 없으면 `y=0`으로 정의한다. 예를 들어 2026-09-01 종료 시점에 예측한다면 그날까지의 거래를 입력으로, 9월 2–10월 1일 구매를 정답으로 삼는다. 기준일 뒤 30일이 완전히 관측되지 않은 고객·시점은 음성으로 처리하지 않고 학습·평가에서 제외한다. 현재 데이터는 2026-10-09까지이므로 마지막 날짜를 기준으로 미래 30일 정답을 만들 수 없다.

현재 Inactive 그룹을 정답 ‘이탈’로 삼으면 현재 RFM 규칙을 다시 학습하는 문제가 생긴다. 비활성은 과거 구매 공백의 표시일 뿐 확정 이탈이 아니므로 미래 재구매를 별도로 관측한다.

| 고객별 후보 피처 | 계산·선정 이유 |
| --- | --- |
| Recency | T에서 마지막 구매까지의 일수; 최근 활동 정도 |
| Frequency·Monetary | T 이전 동일 길이의 구간(예: 90일)에서 고유 주문 수·양수 구매 금액; 거래 행 중복 방지 |
| 평균 주문 금액 | 주문별 행 금액 합계의 평균; 방문 빈도와 지출 규모 구분 |
| 구매 간격 평균·표준편차 | 구매 날짜 간 간격을 고객별 집계; 정상 구매 주기와 규칙성. 구매가 부족하면 결측·횟수 표시 |
| 가입 후 경과 일수 | 신규·장기 고객의 관측 기회 차이 설명. 합성 가입일로 실제 효과를 주장하지 않음 |
| 구매 카테고리 수·주요 카테고리 비중 | 구매 관심의 다양성·집중도 |
| 상품명 길이·단어 수의 구매 상품 평균 | 텍스트의 단순 수치 요약; 상품군 대리변수일 수 있으며 구매 의도를 직접 측정한 값은 아님 |
| image_mean·image_std의 구매 상품 평균 | 구매한 상품 이미지의 밝기·변동 요약; 이미지 품질·고객 선호를 의미한다고 가정하지 않고 추가 가치 검증 |
| 결측 플래그·관측 주문 수 | 대치 여부와 피처 신뢰도 구분 |

거래·상품 피처는 T 이전 구매 상품을 기준으로 고객 단위로 집계한다. 날짜가 다른 상품 메타데이터·평점·배송 결과를 쓴다면 당시 실제로 알 수 있었던 값만 쓴다. 고객 ID는 연결 키로 사용하고 모델 입력에서는 제외한다. RFM 점수·세그먼트는 원래 R/F/M으로부터 파생되므로 중복 정보이며, 처음에는 원래 수치로 시작하고 추가 피처의 가치는 검증 구간에서 비교한다.

**검증 설계**: 과거 T들을 학습, 그 이후 T들을 검증·테스트로 나누고, 학습 정답의 30일 관측이 검증 예측 시점 전에 끝나도록 시점 사이에 간격을 둔다. 같은 고객의 여러 시점 행을 무작위로 섞으면 기간·고객 정보가 겹쳐 성능이 낙관적으로 보일 수 있다. 기존 고객의 다음 구매 예측과 처음 보는 고객으로의 일반화는 평가 목적을 구분한다. 대치·표준화·피처 선택은 학습 데이터에서만 학습한다.

전체 고객에게 같은 재구매 확률을 주는 베이스라인과 비교하고, 재구매가 드물면 PR-AUC·상위 추천 고객의 precision/recall, 확률을 활용하면 calibration을 확인한다. 운영 임계값은 메시지 비용과 추가 이익을 고려해 결정한다. 예측 정확도가 높아도 캠페인의 인과 효과를 입증하지는 않으므로 실제 액션은 대조군 실험으로 검증한다. 이 미션의 합성 패턴으로 얻은 성능은 실제 고객 예측 성능의 근거가 아니다. 현재는 타깃·피처·검증 설계만 제안하며 모델은 학습하지 않았다.
