02 / DATA GRAIN

한 행은 주문일까, 상품 한 줄일까?

주문 O1에서 컵과 접시를 샀다면 거래 표에 두 행이 생깁니다. 둘은 같은 주문이지만 상품이 다릅니다. 이때 행 수를 구매 횟수로 세면 O1을 두 번 구매한 것으로 잘못 계산합니다.

고객주문날짜상품행 금액

AO110월 1일접시10,000원

거래 표

transactions.csv에는 누가 언제 어떤 상품을 몇 개 얼마에 샀는지가 있습니다. 같은 상품이 여러 행에 나타날 수 있습니다.

상품 표 + 이미지 배열

products.csv에는 상품당 하나의 속성이 있습니다. 거래의 product_id로 연결하고, 상품의 image_index로 이미지 위치를 찾습니다.

두 종류의 연결을 구분하세요.
거래 → 상품은 ID로 연결합니다. 상품 → 이미지 배열은 0부터 시작하는 정수 위치로 연결합니다. P010이라는 문자열을 그대로 배열 인덱스로 쓸 수는 없습니다.

merge(..., how="left", validate="many_to_one")는 거래 행을 유지하며 상품을 붙이고, 여러 거래가 하나의 상품을 참조하는 관계인지 검사합니다. 상품 ID가 중복되면 한 거래가 여러 행으로 불어나 금액이 중복 집계될 수 있습니다. _merge 검사에서는 연결되지 않은 상품을 거부합니다.

np.isclose는 부동소수점의 작은 차이를 허용해 “행 금액 ≈ 단가 × 수량”을 검사합니다. 한 주문 ID에 서로 다른 고객이나 날짜가 있으면 오류를 냅니다. 잘못된 날짜는 로드 시 결측 날짜로 변환되어 RFM 대상에서 제외됩니다.

03 / READING PYTHON

DataAnalyzer는 데이터를 담고 일하는 객체

class는 설계도이고, DataAnalyzer(...)로 만든 analyzer는 그 설계도에 따라 생성된 객체입니다. 이 객체 안에 경로, 거래 표, 상품 표, 이미지 배열, 고객별 결과를 함께 보관합니다.

__init__는 객체를 만들 때 실행됩니다. self.df = None은 “이 객체의 거래 표는 아직 없다”는 뜻입니다. CSV를 읽는 일은 여기서 하지 않고 load_data()가 맡습니다. 이 구분 덕분에 객체 생성과 실제 파일 읽기를 따로 이해할 수 있습니다.

현재 작업 중인 거래 표. df는 DataFrame을 줄여 쓴 이름입니다.
self.raw_df
조인·형 변환 후, 결측치 대치 전 표의 사본입니다. CSV 원문 바이트를 보존한 파일은 아닙니다.
self.products
상품당 한 행인 표. 상품 속성의 결측치 통계는 여기서 계산합니다.

고객당 한 행인 집계 표. 거래 행과 다른 단위입니다.

return
계산한 값을 호출한 곳에 돌려줍니다. 함수 이름 뒤 괄호는 그 기능을 실행합니다.

이 코드에서 자주 만나는 기호

표현읽는 방법

04 / MISSING VALUES

비어 있는 값을 무엇으로 채울까?

가격이 없다고 0원을 넣으면 평균 가격이 내려갑니다. 다른 카테고리의 가격을 넣으면 상품 특성이 섞일 수 있습니다. 이 구현은 같은 카테고리의 중앙값을 사용합니다. 중앙값은 정렬했을 때 가운데 값이며, 관측값이 짝수 개면 가운데 두 값의 평균입니다.

여기서 먼저 정할 것은 “상품을 기준으로 계산하는가, 판매 행을 기준으로 계산하는가?”입니다. 상품 속성은 상품 표에서 계산해야 많이 팔린 상품에 가중치가 붙지 않습니다.

같은 상품이 더 많이 팔려도 상품 기준 중앙값은 같아야 합니다

별도 설명 예제: Home 상품 P1=10, P2=40, P3=결측. P2는 한 번 팔리고 P1의 판매 행 수만 바꿉니다. P3에 들어갈 보완값을 비교하세요.

상품 기준 · 구현이 사용하는 값
판매 행 기준 · 이 속성에 쓰면 생기는 왜곡

  1. 컬럼 전체의 통계값 global_value를 준비합니다.
  2. 카테고리별 통계를 transform으로 각 원래 행에 맞춰 가져옵니다.
  3. 결측치는 그룹 값으로 채우고, 그룹도 모두 비었다면 전체 값으로 채웁니다.
  4. 컬럼 전체가 비었다면 임의 숫자를 만들지 않고 오류를 냅니다.

self.products에서 보완한 값을 product_id.map(...)으로 거래 표에 다시 붙입니다. 배송 일수는 거래마다 달라지는 값이므로 거래 표에서 대치합니다. 실제 기본 실행은 카탈로그 가격 12개·평점 7개·배송 일수 272개를 보완했습니다.

거래 금액을 상품 가격으로 다시 만들지 않습니다. 카탈로그 가격은 상품의 참고 속성이고, 거래 금액은 그때 실제 기록된 구매 사실입니다. 결측치 대치 때문에 고객 매출이 바뀌면 안 됩니다. 고객 ID·날짜·구매 금액은 자동 추정하지 않습니다.

설명 예시

agg는 그룹별 한 개의 집계값으로 줄인다. transform은 각 행이 속한 그룹의 중앙값을 원래 행의 위치에 맞춰 반복해서 반환한다. 결측 행을 채울 때는 transform의 결과를 바로 대응시킬 수 있다.

05 / VECTORIZATION

이미지도 숫자 배열이다

이 프로젝트의 이미지 형태는 (80, 16, 16, 3)입니다. 왼쪽부터 상품 수, 높이, 너비, RGB 채널입니다. 상품 축 0을 유지하고 축 1·2·3을 줄이면 상품마다 숫자 하나가 남습니다.

(상품, 높이, 너비, 채널) → mean(axis=(1, 2, 3)) → (상품,)
80장에 대해 평균 80개를 얻습니다. 표준편차도 같은 방식입니다. 모든 축을 줄이면 전체 이미지 배치의 평균 하나만 남아 상품을 구분할 수 없습니다.

tuple(range(1, self.images.ndim))은 “첫 축을 제외한 나머지 축 번호”입니다. RGB 배치는 (1,2,3), 흑백 배치는 (1,2)가 됩니다. image_mean[indices]는 해당 상품의 통계를 판매 행마다 찾아 붙입니다. 문자열 길이와 단어 수는 상품명에서 별도 파생 컬럼으로 만듭니다.

밝기와 픽셀 변동을 따로 바꿔 보세요

별도 설명 이미지: 2×2 회색 픽셀을 RGB 세 채널에 같은 값으로 넣습니다. 기본값 [20, 40, 60, 80]의 평균은 50, 표준편차는 약 22.36입니다. Python과 동일하게 ddof=0을 사용합니다.

Mean · 평균
Std · 표준편차

모두 같은 값 50인 이미지와 [20,40,60,80] 이미지는 평균이 같지만 표준편차는 다릅니다. 평균 하나로 이미지를 충분히 설명할 수 없다는 뜻입니다. 이 통계는 픽셀의 밝기·변동만 요약하며 상품 의미나 사진 품질을 판단하지 않습니다.

이 코드는 실제 사진을 다운로드하지 않고 난수 배열로 이미지를 생성합니다. 브로드캐스팅은 크기가 다른 배열의 축을 맞춰 함께 연산하는 기능입니다. Python에서 픽셀을 하나씩 반복하기보다 NumPy가 전체 배치를 처리하도록 합니다. 데이터 생성이나 컬럼 처리에 반복문이 있는 것과 이미지 통계에 픽셀 반복문을 쓰는 것은 구분하세요.

설명 예시

상품 축까지 함께 줄어들어 이미지 전체에 대한 숫자 하나가 나온다. 각 상품이 어떤 이미지 평균을 갖는지 구분할 수 없다. 현재 코드는 상품 축을 유지해 상품별 피처를 만든다.

06 / OUTLIERS

멀리 떨어진 값이 반드시 오류일까?

IQR은 가운데 50%가 차지하는 범위입니다. Q1은 25백분위, Q3은 75백분위입니다. 경계 밖의 값을 이상치 후보로 표시합니다. 이 방법은 “다른 값에서 얼마나 떨어져 있는가”를 판단하며 기록 오류 여부를 판정하지는 않습니다.

IQR = Q3 − Q1
하한 = Q1 − k × IQR
상한 = Q3 + k × IQR

큰 값과 경계 배율을 바꿔 보세요

별도 설명 데이터 [1,2,3,4,x]. 사분위수는 Pandas 기본과 같은 선형 보간으로 계산합니다. 기본 x=100, k=1.5이면 Q1=2, Q3=4, 경계는 −1과 7입니다.

원래 값이상치 후보?비교용 클리핑 값

flag는 각 행에 True/False를 붙인 조건입니다. detect_outliers()는 표시 컬럼을 추가하고 후보 행의 사본을 돌려줍니다. 원래 가격이나 배송 일수는 덮어쓰지 않습니다.

clip은 경계보다 큰 값을 상한으로, 작은 값을 하한으로 바꾼 비교용 Series를 반환합니다. remove는 경계 안에 있는 값만 담은 비교용 Series를 반환합니다. 호출만으로 self.df의 원본 행이 삭제되지는 않습니다.

기본 분석에서는 배송 일수 15행을 이상치 후보로 표시했고, 단가 후보는 0행이었습니다. 고가 상품이 있어도 해당 분포의 IQR 경계를 넘지 않으면 표시되지 않습니다. 배송 박스플롯의 처리 후 값은 비교용이며 RFM 구매 금액은 원래 값을 유지합니다.

설명 예시

정상적으로 많이 산 우수 고객의 거래가 사라질 수 있다. 고객의 Monetary가 낮아지고 VIP 판단도 달라진다. 탐지한 뒤 원본 오류인지 정상 고가 거래인지 확인해야 한다.

07 / CUSTOMER AGGREGATION

구매 내역을 고객 한 행으로 바꾸기

R은 마지막 구매에서 기준일까지 지난 날짜 수, F는 관측 기간의 고유 주문 수, M은 관측 기간의 양수 구매 금액 합계입니다. 최근에 샀을수록 R은 작습니다. 많이 샀을수록 F·M은 큽니다.

첫 대화의 다섯 거래를 직접 계산해 보세요

고객주문거래일행 금액
먼저 A의 R·F·M을 계산한 뒤 버튼을 눌러 확인하세요.
고객R · 일수F · 횟수M · 원

고객·주문·날짜가 존재하고 금액·수량·단가가 양수인 구매만 집계합니다. 기본 기준일은 마지막 유효 거래일의 다음 날입니다. 기준일보다 뒤의 거래가 있으면 미래 정보를 포함하게 되므로 이 구현은 오류를 냅니다. 과거 시점의 분석을 하려면 입력 거래를 먼저 그 시점까지 제한해야 합니다.

groupby(customer_col)은 같은 고객끼리 묶습니다. max는 가장 최근 거래일, nunique는 중복 없는 주문 수, sum은 행 금액 합계입니다. 이 집계로 거래 2,842행이 고객 240행으로 바뀝니다.

양수 구매 합계는 반품을 차감한 순매출이나 평생가치(LTV)가 아닙니다. 고객마다 관측 기간이 다를 수 있으므로 가입일·관측 시작일이 없으면 F·M 비교에도 한계가 있습니다. 합성 데이터의 그룹을 실제 고객에 그대로 적용하기 전에 구매 주기를 검토해야 합니다.

설명 예시

입력 거래가 같다면 모든 고객의 R이 1일 늘어난다. 주문 수와 금액은 그대로이므로 F와 M은 바뀌지 않는다. 최근 구매 경계에 걸친 고객은 그룹이 달라질 수 있다.

08 / SCORING AND POLICY

점수 계산과 그룹 정책은 서로 다른 결정

RFM 원래 값의 단위는 일·회·원으로 다릅니다. 이 구현은 각 값을 평균 순위 백분위로 바꾸고 1–5점으로 요약합니다. 동점에는 같은 점수를 줍니다. 점수별 인원이 반드시 같지는 않습니다.

ascending=False인 R은 큰 경과 일수에 낮은 순위를 주고 작은 값에 높은 순위를 줍니다. F·M은 반대로 큰 값에 높은 순위를 줍니다. 백분위 × 5를 올림한 뒤 1–5 범위에 제한합니다. 예를 들어 R=[1,10,10]이면 R 점수는 [5,3,3]입니다. 모든 값이 같으면 n에 따라 같은 점수를 받으며 항상 3점이라고 단정할 수는 없습니다.

그룹은 점수 합이 아니라 아래 조건으로 정합니다. 조건 순서도 정책입니다. 오래 구매하지 않은 고객은 F가 높아도 Inactive가 먼저 적용됩니다. np.select는 처음 True인 조건을 선택합니다.

실제 합성 고객 240명의 분류 기준을 바꿔 보세요

현재 저장된 R·F·M을 유지하고 분류 정책만 다시 계산합니다. Python 실행 결과를 바꾸거나 학습 모델을 훈련하는 기능은 아닙니다. VIP 금액 경계 1,786,650원은 고정합니다.

    분류 인원 변화는 정책의 영향을 보여줍니다. 인원이 달라졌다고 실제 성과가 좋아졌다는 뜻은 아닙니다.

    고객 표에서 다시 그룹별로 집계해 고객 수·평균 R/F/M·매출 비중을 얻습니다. 이때 고객당 한 행이므로 size는 고객 수입니다. 같은 size라도 어떤 단위의 표에서 세는지에 따라 의미가 달라집니다.

    설명 예시

    Inactive다. R>90 조건을 먼저 검사하고, np.select는 첫 번째 참 조건을 선택한다. 자주 구매했던 고객이어도 현재 구매 공백을 우선해 분류하는 정책이다.
