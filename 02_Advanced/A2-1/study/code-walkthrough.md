### 0-2. shape 읽는 법

NumPy 배열(`ndarray`)은 같은 종류의 숫자를 여러 축으로 늘어놓은 것이다. `shape`은 축마다의 길이, `ndim`은 축의 개수다.

| 표기 | 뜻 | 이 미션의 예 |
| --- | --- | --- |
| `()` | 숫자 하나(스칼라) | 손실 `L`, 출력 `z2` |
| `(2,)` | 숫자 2개짜리 벡터 | 입력 `x`, 은닉값 `a1`, 기울기 `grad` |
| `(2, 2)` | 2행 2열 행렬 | `W1`, 변환 행렬 `A` |
| `(2, N)` | 2행 N열: 열 하나가 점 하나 | 단위 원 100점 `(2, 100)` |
| `(T+1, 2)` | 행 하나가 반복 한 번의 위치 | 최적화 경로 `(101, 2)` |
| `(m, n)` | 흑백 이미지 | `(128, 128)` |

`axis`는 "어느 축을 따라 계산해 없앨지"를 고른다. 설명용 예:

```text
a = [[1, 2, 3],
     [4, 5, 6]]          shape (2, 3)

a.sum(axis=0) = [5, 7, 9]     0축(행 방향)을 더해 없앰 → (3,)
a.sum(axis=1) = [6, 15]       1축(열 방향)을 더해 없앰 → (2,)
a.sum()       = 21            모든 축을 없앰 → ()
```

**브로드캐스팅**은 shape이 다른 배열끼리 계산할 때 길이 1인 축(또는 없는 축)을 늘려 맞추는 규칙이다. `(m, k) * (k,)`는 각 행에 같은 `(k,)`를 곱하고, `(4, 6) − (4, 1)`은 각 행에서 그 행의 값 하나를 뺀다. SVD([1-3](#1-3-svd-압축))와 소프트맥스([5-1](#5-1-소프트맥스))에서 쓴다.

**새 배열인가, 원본이 바뀌는가.** `A @ B`, `x - lr * g`, `np.clip(...)`처럼 연산 결과를 변수에 담으면 새 배열이 생기고 원본은 그대로다. 반대로 `x[idx] = 값`, `self.W1 -= ...`는 기존 배열을 그 자리에서 바꾼다. 이 미션에서 원본을 바꾸는 곳은 `numerical_gradient`의 복사본 `x`(바꾼 뒤 되돌림)와 `TwoLayerNet.sgd_step`, 옵티마이저의 상태(`self.v`, `self.m`)뿐이다.

## 1. 선형대수 (linear_algebra.py)

### 1-1. 행렬 변환과 면적

**해결하는 문제.** 미션은 회전·스케일링·전단 행렬로 도형을 바꾸고 "행렬식(det)과 면적 변화의 관계"를 확인하라고 한다.

**데이터 흐름.** [unit_circle](../src/linear_algebra.py#L29) → [transform_points](../src/linear_algebra.py#L95) → [polygon_area](../src/linear_algebra.py#L131) → [area_ratio_check](../src/linear_algebra.py#L155)

```text
unit_circle()          (2, 100)  0행 = cos θ, 1행 = sin θ
A @ points             (2, 2) @ (2, 100) → (2, 100)   새 배열, 원본 원은 그대로
polygon_area(points)   (2, 100) → 숫자 하나
ratio = after / before → 숫자 하나, |det|와 비교
```

설명용 예. 스케일링 `S(2, 0.5)`는 점 (1, 0)을 (2, 0)으로, (0, 1)을 (0, 0.5)로 옮긴다. det = 2·0.5 − 0·0 = 1이다. 가로로 2배, 세로로 0.5배라 면적은 그대로다.

실행 결과. 100점짜리 원은 첫 점과 끝 점이 같아서 실제로는 **99각형**이고 면적이 π(3.1416)가 아니라 3.1395다. 그래도 면적비는 정확히 맞는다. 선형 변환은 원이든 다각형이든 모든 도형의 면적을 같은 배율 |det|로 바꾸기 때문이다.

| 행렬 | det | 변환 전 면적 | 변환 후 면적 | 면적비 |
| --- | ---: | ---: | ---: | ---: |
| S(2, 0.5) | 1 | 3.1395 | 3.1395 | 1.0000 |
| [[0, 2], [1, 0]] | −2 | 3.1395 | 6.2790 | 2.0000 |

**왜 det≠1인 행렬을 추가했나.** 요구된 세 변환은 모두 det = 1이다. 결과가 1.0만 나오면 "면적비 = |det|"인지 "변환해도 면적이 안 변한다"인지 구별할 수 없다. 그래서 [run_all.py:118](../src/run_all.py#L118)에서 det = 5, −2인 행렬을 더 확인한다. det = −2인데 면적비가 +2인 것은 부호가 "방향 뒤집힘"을 뜻하기 때문이다.

**해석 범위.** 신발끈 공식은 꼭짓점이 순서대로 이어진 단순 다각형에서만 맞다. 점의 순서가 섞이면 엉뚱한 값이 나온다.

### 1-2. Power Iteration

**해결하는 문제.** `np.linalg.eig` 없이 가장 큰 고유값을 직접 구한다. eig는 [compare_with_numpy_eig](../src/linear_algebra.py#L338)에서 정답 확인에만 쓴다.

**반복 한 번의 데이터 흐름.** [power_iteration](../src/linear_algebra.py#L264)

```text
b (n,) 길이 1 → Ab = A @ b (n,) → norm = ‖Ab‖ (숫자) → b_next = Ab / norm (n,) 길이 1
                                                      → λ 추정 = b @ A @ b (숫자)
```

설명용 추적. A = [[4, 1], [1, 3]], 시작 벡터를 단순하게 [1, 0]으로 둔다(실제 실행은 seed 42 난수 벡터에서 시작).

| t | A @ b | ‖A b‖ | 새 b | λ 추정 bᵀAb |
| ---: | --- | ---: | --- | ---: |
| 1 | [4, 1] | 4.1231 | [0.9701, 0.2425] | 4.4118 |
| 2 | [4.1231, 1.6977] | 4.4590 | [0.9247, 0.3807] | 4.5592 |
| 3 | [4.0795, 2.0669] | 4.5732 | [0.8920, 0.4520] | 4.6021 |
| … | | | → [0.8507, 0.5257] | → 4.6180 |

b가 정답 고유벡터 쪽으로 조금씩 돌고, λ 추정이 4.618로 다가간다. 두 고유값이 4.618과 2.382라서 비율 0.516만큼씩 다른 성분이 줄어든다(대칭 행렬에서 고유값 오차는 그 제곱 0.266씩). 실행 결과는 23회 만에 tol 1e-6을 만족했다.

**왜 매번 길이로 나누나.** 나누지 않으면 b의 길이가 4.618ᵗ로 커져 수백 번 뒤 overflow가 난다. 방향만 필요하므로 길이를 1로 되돌린다.

**왜 부호를 맞추나.** 고유값이 음수면 A를 곱할 때마다 방향이 뒤집혀 `b_next − b`가 줄지 않는다. 같은 축이면 수렴으로 보도록 `b_next + b`도 본다([linear_algebra.py:318](../src/linear_algebra.py#L318)).

**해석 범위.** 가장 큰 |λ| 하나만 구한다. 크기가 같은 고유값이 둘이면(예: 2와 −2) 수렴하지 않고, 시작 벡터가 정답 방향과 정확히 직교해도 실패한다.

### 1-3. SVD 압축

**해결하는 문제.** 이미지를 큰 특이값 몇 개로 근사해 "저장량을 줄이면 화질이 얼마나 떨어지는가"를 본다.

**shape 흐름.** [svd_compress](../src/linear_algebra.py#L371), 실행 결과 128×128 이미지 기준

| 단계 | 코드 | shape |
| --- | --- | --- |
| 입력 | `A` | (128, 128) |
| 분해 | `U, S, Vt = np.linalg.svd(A, full_matrices=False)` | (128, 128), (128,), (128, 128) |
| 앞 k개 | `U[:, :k]`, `S[:k]`, `Vt[:k, :]` | (128, k), (k,), (k, 128) |
| 열마다 σ 곱하기 | `U[:, :k] * S[:k]` (브로드캐스팅) | (128, k) |
| 근사 | `... @ Vt[:k, :]` | (128, 128) |
| 픽셀 범위로 자르기 | `np.clip(approx, 0, 1)` | (128, 128), 새 배열 |

S는 대각 행렬이 아니라 큰 순서로 정렬된 특이값만 담은 1차원 배열이다. 실행 결과 첫 세 값은 47.6, 12.3, 11.6이고 마지막 값은 0.001이다. 첫 성분 하나가 이미지의 큰 밝기 구조를 대부분 담는다.

설명용 예. A = [[3, 0], [0, 1]]이면 σ = [3, 1]이다.

```text
k = 1:  A_1 = 3·u₁v₁ᵀ = [[3, 0], [0, 0]]
상대 오차 = ‖A − A_1‖ / ‖A‖ = √1 / √(9 + 1) = 0.316
에너지 보존 = 3² / (3² + 1²) = 0.9
```

**저장 비율.** 원본은 m·n개, 근사는 U의 m·k + σ의 k + V의 n·k개를 저장한다. 128×128에서 k = 10이면 10·257 / 16384 = 0.157이다. k = 100이면 1.57로 원본보다 크다. 화질 지표만 보고 "k = 100이 좋은 압축"이라고 해석하면 안 된다.

**해석 범위.** 상대 오차와 에너지는 자르기 전 근사로, PSNR은 0~1로 자른 이미지로 계산한다([linear_algebra.py:404](../src/linear_algebra.py#L404) 아래). 실제 이미지 압축 형식(JPEG 등)은 다른 방식을 쓰므로 이 숫자를 파일 크기 비교로 옮기면 안 된다.

### 2-1. 중심차분

[numerical_derivative](../src/calculus.py#L19)

| 함수, 위치, h | 계산 | 결과 | 정답과 차이 |

| x², 3, 0.1 (설명용) | (9.61 − 8.41) / 0.2 | 6.0 | 0 |
| sin, 1, 0.1 중심차분 (설명용) | (sin 1.1 − sin 0.9) / 0.2 | 0.5394 | 9.0e-4 |

같은 h에서 중심차분이 약 50배 정확하다. x²에서는 오차 항이 정확히 사라지므로, h에 따른 오차 실험([run_all.py:225](../src/run_all.py#L225))은 sin을 쓴다. h를 1e-12처럼 너무 작게 하면 거의 같은 두 수를 빼면서 유효숫자를 잃어 오히려 오차가 커진다.

### 2-2. 좌표별 Gradient

[numerical_gradient](../src/calculus.py#L39)는 칸을 하나씩 ±h 움직인다. 설명용으로 f(x, y) = x² + y², point = (1, 2)를 따라가면:

| 반복 | idx | x 임시 값 | f_plus, f_minus | grad[idx] |
| --- | --- | --- | --- | ---: |
| 1 | (0,) | (1±h, 2) | 5 + 2h + h², 5 − 2h + h² | 2 |
| 2 | (1,) | (1, 2±h) | 5 + 4h + h², 5 − 4h + h² | 4 |

`x[idx] = original`로 매번 되돌리므로, 다음 칸을 미분할 때 앞 칸의 이동이 섞이지 않는다. `np.ndindex`를 쓰기 때문에 같은 함수가 (2, 2) 가중치 행렬에도 그대로 동작한다.

### 2-3. 등고선과 수직

[gradient_contour_orthogonality](../src/calculus.py#L165)

```text
pts       (2, 24)  등고선 위 점 (이분법으로 찾음)
tangents  (2, 24)  각도 ±δ 점의 차이 = 등고선 방향
grads     (2, 24)  점마다 numerical_gradient (2,)를 열로 붙임
grads * tangents → (2, 24) → sum(axis=0) → (24,)   점마다 내적
cos       (24,)    0에 가까우면 수직
```

실행 결과 최대 |cos|는 9.6e-12다. 접선과 Gradient를 서로 다른 방법으로 구했으므로 독립적인 확인이다. 등고선을 따라 움직이면 f가 변하지 않으므로 그 방향의 기울기 성분이 0이어야 한다. 그래서 −Gradient(경사하강 방향)는 항상 등고선을 가로지른다.

## 3. 신경망 (neural_net.py)

**해결하는 문제.** 학습 루프 한 바퀴(예측 → 손실 → 기울기)를 손계산 가능한 크기로 직접 구현하고, 결과를 손계산·수치 미분과 맞춘다.

**객체와 메서드.** [TwoLayerNet](../src/neural_net.py#L82)은 가중치 네 개를 객체 안(`self.W1` 등)에 보관한다. `forward`와 `backward`는 가중치를 읽기만 하고, `sgd_step`만 가중치를 바꾼다.

실행 결과(고정 예제, 노트북 4절 표와 같다):

| 단계 | 코드 | shape | 값 |
| --- | --- | --- | --- |
| 입력 | `x` | (2,) | [1, 0] |
| 은닉 선형 | `W1 @ x + b1` | (2,2)@(2,) → (2,) | [0.1, 0.3] |
| 은닉 활성 | `sigmoid(z1)` | (2,) | [0.5250, 0.5744] |
| 출력 선형 | `W2 @ a1 + b2` | (2,)@(2,) → () | 0.6072 |
| 예측 | `sigmoid(z2)` | () | 0.6473 |
| 손실 | BCE | () | 0.4350 |
| ∂L/∂z2 | `dL_dy_pred * ŷ(1−ŷ)` | () | −0.3527 (= ŷ − y) |
| ∂L/∂W2 | `dL_dz2 * a1` | () × (2,) → (2,) | [−0.1852, −0.2026] |
| ∂L/∂a1 | `dL_dz2 * W2` | (2,) | [−0.1764, −0.2116] |
| ∂L/∂z1 | `dL_da1 * a1 * (1 − a1)` | (2,) 원소별 곱 | [−0.0440, −0.0517] |
| ∂L/∂W1 | `np.outer(dL_dz1, x)` | (2,),(2,) → (2,2) | [[−0.0440, 0], [−0.0517, 0]] |

**읽는 법.** 기울기가 음수라는 것은 "그 가중치를 키우면 손실이 준다"는 뜻이다. 정답이 1인데 예측이 0.647이라 출력을 키우는 쪽으로 모든 기울기가 음수다. `W1`의 둘째 열이 0인 것은 입력 x₂ = 0이라 그 연결이 이번 예측에 쓰이지 않았기 때문이다.

**`*`와 `@`를 헷갈리지 않기.** `dL_da1 * a1 * (1 − a1)`은 같은 위치끼리 곱(⊙)이다. 은닉 뉴런 i의 출력은 자기 입력 z1ᵢ에만 의존하므로 행렬 곱이 아니다. 반면 `W1 @ x`는 모든 입력을 섞으므로 행렬 곱이다.

**수치 미분 검증.** [loss_with](../src/neural_net.py#L188)는 가중치 하나만 바꾼 임시 신경망의 손실을 돌려준다. `numerical_gradient`가 W1의 네 칸을 ±h씩 움직여 이 함수를 8번 부르면, 역전파 식 없이 ∂L/∂W1을 잴 수 있다. 실행 결과 두 방법의 최대 차이는 1.1e-11이다.

**한 걸음 갱신.** [sgd_step](../src/neural_net.py#L209)은 `W ← W − lr · ∂L/∂W`를 제자리에서 적용한다. lr = 0.5면 W2는 [0.5, 0.6] → [0.5926, 0.7013]이 되고, 노트북 6절에서 손실이 0.4350 → 0.3395로 준다.

**해석 범위.** 샘플 하나, 뉴런 네 개짜리 예제다. 손실이 준다는 것은 "이 샘플에 대해 맞는 방향으로 움직였다"는 뜻일 뿐, 새 데이터에서도 잘 맞힌다는 뜻(일반화)은 아니다.

## 4. 최적화 (optimizer.py)

**해결하는 문제.** 기울기를 알았을 때 파라미터를 어떻게 움직일지 정하는 규칙들을 비교한다. 신경망의 `sgd_step`과 같은 일을 2차원 함수 위에서 그림으로 보는 실험이다.

**공통 구조.** 모든 옵티마이저는 [Optimizer](../src/optimizer.py#L132)를 상속하고 `step(params, grad)`만 다르게 정의한다. 그래서 [optimize](../src/optimizer.py#L378)는 옵티마이저 종류를 몰라도 같은 반복문으로 돌릴 수 있다.

```text
x0 (2,) → [g = grad_fn(x) (2,) → x = optimizer.step(x, g) (2,) → path에 복사본 추가] × n
→ np.array(path)  (n+1, 2)    path[0] = 시작점, path[-1] = 마지막 위치
```

### 4-1. 같은 시작점에서 첫 세 걸음

실행 조건과 같은 시작점 (5, 5), 첫 3 step만 잘라 본 값이다.

x² + y², lr = 0.1:

| step | VanillaGD | Momentum (β=0.9) |
| ---: | --- | --- |
| 0 | (5, 5) | (5, 5) |
| 1 | (4, 4) | (4, 4) |
| 2 | (3.2, 3.2) | (2.3, 2.3) |
| 3 | (2.56, 2.56) | (0.31, 0.31) |

Momentum 2번째 걸음: 기울기 (8, 8)에 이전 속도 (10, 10)의 0.9배를 더해 v = (17, 17), 이동 1.7. 같은 방향 기울기가 쌓여 빨라진다. 대신 관성 때문에 원점을 지나쳐 진동하므로 이 함수에서는 100회 뒤 GD(1.4e-9)보다 멀다(2.0e-2).

x² + 10y², lr = 0.1:

| step | VanillaGD | Momentum | Adam |
| ---: | --- | --- | --- |
| 0 | (5, 5) | (5, 5) | (5, 5) |
| 1 | (4, −5) | (4, −5) | (4.9, 4.9) |
| 2 | (3.2, 5) | (2.3, −4) | (4.8, 4.8) |
| 3 | (2.56, −5) | (0.31, 4.9) | (4.7, 4.7) |

GD의 y는 매번 1 − 20·0.1 = −1배라 ±5를 영원히 오간다. Adam은 좌표마다 기울기 크기로 나누므로 기울기 (10, 100)이 10배 달라도 두 좌표 모두 0.1씩 움직인다. 첫 걸음은 느려 보이지만 진동하지 않는다.

Newton, x² + 10y²: Hessian [[2, 0], [0, 20]]로 `H d = g`를 풀면 d = (10/2, 100/20) = (5, 5)이고 한 번에 (0, 0)에 도착한다.

### 4-2. 학습률이 결과를 바꾼다

x² + y²에서 GD는 x_{t+1} = (1 − 2·lr)·x_t다([run_all.py:311](../src/run_all.py#L311) 주석).

| lr | 배율 1 − 2·lr | 결과 |
| ---: | ---: | --- |
| 0.1 | 0.8 | 천천히 수렴 |
| 0.5 | 0 | 한 번에 원점 |
| 0.9 | −0.8 | 부호를 바꾸며 수렴 |
| 1.0 | −1 | 같은 크기로 진동 |
| 1.1 | −1.2 | 발산 |

**해석 범위.** "Momentum이 GD보다 빠르다", "Adam이 낫다"는 학습률·β·함수 모양에 따라 뒤집힌다. 실행 결과 x² + 10y²에서 lr = 0.01이면 Momentum이 25배 이상 가깝지만, lr = 0.09면 GD가 더 빠르다. 그래서 [run_all.py:377](../src/run_all.py#L377)에서 학습률 8개를 모두 비교한다. 이 함수들은 2차원 장난감 문제이고, 실제 신경망의 손실 곡면은 훨씬 고차원이다.

## 5. 확률과 손실 (probability.py)

**해결하는 문제.** "회귀는 MSE, 분류는 Cross-Entropy"가 임의 선택이 아니라, 데이터가 어떤 분포에서 나왔다고 가정하느냐에서 나온다는 것을 계산으로 확인한다. 수식 유도는 [probability_loss.ipynb](../notebooks/probability_loss.ipynb) 3–4절에 있다.

### 5-1. 소프트맥스

[softmax](../src/probability.py#L61), 설명용 z = [1, 2, 3]:

```text
max(z) = 3
shifted = z − 3        = [−2, −1, 0]
e = exp(shifted)       = [0.1353, 0.3679, 1.0000]
합                      = 1.5032
e / 합                  = [0.0900, 0.2447, 0.6652]
```

**왜 최댓값을 빼나.** [1000, 1001, 1002]를 그대로 넣으면 e¹⁰⁰⁰이 무한대(inf)가 되고 inf / inf = nan이다. 최댓값을 빼면 가장 큰 지수가 e⁰ = 1이라 넘칠 수 없고, 분자·분모에 같은 수가 곱해지는 것이라 결과는 같다.

**keepdims가 필요한 이유.** 배치 (4, 6)에서 `np.max(z, axis=1)`은 (4,)다. (4, 6) − (4,)는 뒤쪽 축끼리 맞추려다 6 ≠ 4라 오류가 난다. `keepdims=True`로 (4, 1)을 만들면 각 행에서 그 행의 최댓값을 빼는 계산이 된다.

### 5-2. 손실 = 음의 로그우도

[gaussian_nll](../src/probability.py#L102), 설명용 y = [1, 2], ŷ = [1, 3], σ² = 1:

```text
샘플별 −log p(yᵢ | ŷᵢ) = (yᵢ − ŷᵢ)² / 2 + ½·log(2π)
                       = [0 + 0.9189, 0.5 + 0.9189]
합                     = 2.3379
= (1 / 2σ²)·Σ(y − ŷ)² + (n/2)·log(2πσ²) = 0.5 + 1.8379
```

w가 바뀌어도 둘째 항(상수)은 그대로라 NLL을 줄이는 w와 MSE를 줄이는 w가 같다. 실행 결과 둘 다 1.505다. 코드는 미분 대신 w 후보 601개를 모두 대입하는 **격자 탐색**으로 최솟값 위치를 찾고([run_all.py:497](../src/run_all.py#L497)), 정답 Σxy / Σx²로 확인한다.

[bernoulli_nll](../src/probability.py#L125), 설명용 y = [1, 0], p = [0.9, 0.2]: 정답이 나올 확률은 [0.9, 0.8], −log를 더하면 0.105 + 0.223 = 0.329다. 이것이 BCE 합과 같은 식이다.

**해석 범위.** MSE를 쓰면 "잡음이 정규분포"라는 가정을 함께 받아들인 것이다. 이상치가 많은 데이터에서는 이 가정이 맞지 않는다. 실험 데이터는 이 가정에 맞춰 만든 합성 데이터라 두 최적점이 깔끔하게 일치한다.

## 6. 정보 이론 (information.py, 보너스)

[entropy](../src/information.py#L35), [cross_entropy](../src/information.py#L55), [kl_divergence](../src/information.py#L78)는 모두 `nz = p > 0` 마스크로 p가 0인 칸을 빼고 계산한다. 0·log 0은 정의상 0이지만 컴퓨터는 0·(−∞) = nan으로 계산하기 때문이다.

설명용 p = [0.7, 0.3], q = [0.4, 0.6]:

```text
KL(p‖q) = 0.7·log(0.7/0.4) + 0.3·log(0.3/0.6)
        = 0.7·0.5596      + 0.3·(−0.6931)
        = 0.3917 − 0.2079 = 0.1838
```

실행 결과(p = [0.7, 0.2, 0.1], q = [0.4, 0.4, 0.2]): H(p) = 0.8018, KL(p‖q) = 0.1838, H(p, q) = 0.9856 = 0.8018 + 0.1838. 정답 p는 학습 중 바뀌지 않으므로 Cross-Entropy를 줄이는 것은 KL을 줄이는 것과 같다.

## 확인 질문

먼저 답을 예측하고, 필요하면 코드를 바꿔 실행해 본 뒤 펼쳐 확인한다.

**1. shape.** `polygon_area`에 shape (100, 2)인 배열을 넣으면 어떻게 될까?

<details><summary>답</summary>

`x, y = 배열`은 첫 축을 기준으로 나눠 담는다. 첫 축 길이가 100이라 "값이 너무 많다"는 오류(ValueError)가 난다. 이 파일은 점 집합을 항상 (2, N)으로 다룬다는 약속에 기대고 있다.

</details>

**2. 슬라이싱.** `svd_compress`에서 `S[:k_used]` 대신 `S[k_used:]`를 쓰면 무엇이 달라질까?

<details><summary>답</summary>

앞 k개가 아니라 k번 이후의 작은 특이값들이 선택된다. shape도 (128 − k,)가 되어 `U[:, :k_used]` (128, k)와 곱할 수 없어 대부분의 k에서 오류가 난다. k = 64처럼 길이가 우연히 맞으면 오류 없이 엉뚱한 이미지가 나온다. 앞쪽이 큰 특이값이라 `:k`가 "중요한 성분 k개"다.

</details>

**3. 데이터 변화.** `numerical_gradient`에서 `x[idx] = original` 줄을 지우면 (1, 2)에서의 결과는?

<details><summary>답</summary>

첫 칸을 미분한 뒤 x₀이 1 − h로 남는다. 둘째 칸은 (1 − h, 2 ± h)에서 계산되지만 x² + y²에서는 y 방향 기울기가 x와 무관해 여전히 4다. 첫 칸 결과도 2다. 이 함수에서는 우연히 결과가 같지만, x와 y가 섞인 함수(예: x·y)에서는 틀린 값이 나온다. 되돌리기는 "한 번에 한 좌표만 움직인다"는 정의를 지키기 위한 줄이다.

</details>

**4. 원본 변경.** 노트북에서 `net.sgd_step(...)`을 실행한 뒤 `example_network()`를 다시 부르면 가중치는 처음 값일까?

<details><summary>답</summary>

처음 값이다. `TwoLayerNet.__init__`이 `np.array(...)`로 복사본을 만들기 때문에 `sgd_step`이 바꾼 것은 그 객체의 복사본뿐이고 `EXAMPLE` 사전은 그대로다. 반면 이미 만든 `net` 객체를 다시 쓰면 바뀐 가중치가 그대로 남는다.

</details>

**5. 학습률.** x² + y²에서 lr = 0.75면 GD는 어떻게 움직일까?

<details><summary>답</summary>

배율 1 − 2·0.75 = −0.5. 매번 부호가 바뀌며 절반으로 줄어 (5, 5) → (−2.5, −2.5) → (1.25, 1.25) → …로 수렴한다. 수렴 조건은 |1 − 2·lr| < 1, 즉 0 < lr < 1이다.

</details>

**6. Momentum.** β = 0으로 두면 Momentum은 어떤 옵티마이저와 같아질까?

<details><summary>답</summary>

`v = 0·v + g = g`라서 `θ − lr·g`, 즉 VanillaGD와 같다. β는 과거 기울기를 얼마나 남길지 정하는 값이다.

</details>

**7. 소프트맥스.** `softmax([0, 0, 0, 0])`의 결과와, 이것을 정답 분포 one-hot [1, 0, 0, 0]과 비교한 Cross-Entropy는?

<details><summary>답</summary>

모든 점수가 같아 [0.25, 0.25, 0.25, 0.25]다. Cross-Entropy는 정답 확률의 −log이므로 −log 0.25 = log 4 ≈ 1.386이다. 아무 정보 없이 찍을 때의 손실이며, 학습 초기 분류 모델의 손실이 대략 log(클래스 수) 근처에서 시작하는 이유다.

</details>

**8. 해석.** SVD k = 100의 PSNR이 54 dB로 매우 높다. "k = 100으로 압축하면 좋다"고 말할 수 있을까?

<details><summary>답</summary>

아니다. 저장 비율이 1.57이라 원본보다 더 많은 숫자를 저장한다. 화질 지표와 저장량을 함께 봐야 하며, 128×128에서는 k < 63.75일 때만 실제로 줄어든다.

</details>
