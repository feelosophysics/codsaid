# A6-2 HTML 학습 자료

`a6-2.html` 파일 하나만 브라우저에서 열면 된다. 인터넷 없이 읽고 조작할 수 있다. 실험 수치, 손실 곡선, 시계열 원자료, 오분류 사진 썸네일, 결과 그림, 코드 발췌가 모두 파일 안에 들어 있다(약 1.6MB). 휴대폰 화면 폭(375px)에서도 가로로 넘치지 않는다.

## 학습 순서

결론과 큰 그림을 먼저 보고, 그 결론을 만든 도구로 내려가는 탑다운 순서다.

1. **큰 그림**: 1장에서 성능 개선 사이클과 세 데이터의 결론을 본다. AAPL은 Naive와 같고, 서울 기온은 딥러닝이 이기고, 꽃은 사전학습이 결정적이다.
2. **기준선 감각**: 2장 베이스라인 실험실에서 SMA 창과 EMA α를 바꿔 본다.
3. **진단**: 3장에서 수준값 예측이 망가지는 이유(MinMax 외삽)를 보고, 4장 진단기로 실제 곡선을 하나씩 진단한다.
4. **정량화**: 5장에서 개선율과 Diebold-Mariano 검정을 읽는다.
5. **누수**: 6장 윈도우 실험실에서 체크포인트를 하나씩 어겨 보고, 실제로 어긴 실험의 점수를 확인한다.
6. **이미지 트랙**: 8장에서 사진 수와 Freezing 범위를 비교하고, 9장에서 오분류 사진을 태그별로 본다.
7. **보너스**: 10장 Grid vs Random, 11장 Attention 가중치를 본다.
8. **설명 연습**: 13장의 미션 목표 6문항에 답해 본다.

## 위젯

- 베이스라인 실험실: AAPL·서울 기온의 실제 Test 구간에서 MAE·RMSE·MAPE를 바로 계산한다
- MinMax 외삽 보기: Scaler를 Train만으로 fit한 경우와 전체 기간으로 fit한 경우를 비교한다
- 진단기: 값을 넣는 진단기와, 실제 손실 곡선 24개(시계열 14개, 이미지 10개)를 골라 진단하는 뷰어
- 개선율 표: 데이터별 베이스라인 9개 대비 개선율과 DM 검정
- 윈도우·분할 실험실: 누수 체크포인트 4개를 하나씩 어겨 본다
- Layer Freezing 탐색기: ResNet18 블록별 파라미터 수와 사진 수별 결과
- 오분류 갤러리: 태그별로 거르는 썸네일과 오차 분석표 전체
- Grid vs Random: 같은 예산 9회로 두 탐색 방법을 비교한다
- 하이퍼파라미터 탐색 결과 산점도, Attention 가중치 그래프

본문의 숫자와 결과에 따라 달라지는 해설은 빌드할 때 넣은 결과 데이터에서 읽어 온다. 그래서 실험을 다시 돌리고 빌드하면 함께 바뀐다.

## 재생성과 검증

상위 A6-2 폴더에서 실행한다.

```powershell
uv run python tools/build_study_guide.py
uv run python tools/verify_study_guide.py
```

`a6-2.template.html`이 설명과 화면의 편집 원본이다. 빌드 도구는 여기에 결과 JSON, 오분류 썸네일, 256색으로 줄인 그림, 코드 발췌를 넣는다. 원본 해시는 `source-manifest.json`에 저장한다.

검증 도구는 다음을 확인한다. Node.js가 필요하다.

- **파일 대조**: 매니페스트 해시와 현재 파일(소스, 결과 JSON·CSV, 태그, 그림)을 비교한다.
- **코드 발췌**: HTML 속 발췌가 현재 원본 줄과 같은지 확인한다.
- **페이지 구조**: 내부 링크 대상, 입력 요소의 레이블, 스크립트가 찾는 id를 확인한다. 외부 리소스가 없는지, 본문에 'Val'·'Dev' 같은 금지 용어가 없는지도 본다.
- **계산 대조**: `<script id="mathlib">`을 Node.js로 실행해 Python 결과와 비교한다.
  - 베이스라인 9개 × 데이터 2개 × Train/Validation/Test × MAE·RMSE·MAPE (상대 오차 1e-6 이내)
  - 진단 규칙 격자 882점
  - 개선율
  - MinMax Test 최댓값

일부러 틀린 계산(SMA 값에 1.000001 곱하기, 진단 규칙 하나 뒤바꾸기)을 넣으면 626건이 실패로 잡히는 것을 확인했다.
