# A4-2 글에서 정보와 기분 뽑기: 규칙으로 언어를 정의할 수 있을까?

고객 문의나 리뷰 문장에서 연락처, 날짜, 금액을 뽑고, 글쓴이의 기분이 좋은지 나쁜지 판단하는 프로젝트예요. 학습된 모델 없이 사람이 쓴 규칙만 사용해요. 글자 모양은 **정규표현식**으로 찾고, 기분은 단어별 점수표인 **감성 사전**으로 계산해요.

> **먼저 알아 두세요.** 감성 분석 점수는 네이버 영화 리뷰(NSMC)로 잰 값이에요. 고객 문의로 잰 성능이 아니에요. 정보 추출 점수는 직접 쓴 시험 문장의 결과라서, 실제 문서에서도 같은 점수가 나온다고 볼 수는 없어요. 문장에 나오는 연락처와 개인정보는 모두 지어낸 값이에요.

## 한눈에 보는 결과

| 하는 일 | 시험 데이터 | 결과 |
| --- | --- | --- |
| 정보 추출 (이메일, 전화번호, 날짜, 금액, URL) | 직접 쓴 80문장, 정답 88개 | F1 **0.906** (정밀도 0.939, 재현율 0.875) |
| 감성 분석 (긍정, 부정) | NSMC 리뷰 1,000건 | 정확도 **76.2%** (미션 필수 규칙만 쓰면 73.3%) |

- **정밀도:** 찾은 것 중 진짜의 비율이에요.
- **재현율:** 진짜 중 찾아낸 비율이에요.
- **F1:** 정밀도와 재현율을 하나로 합친 점수예요. 둘 중 낮은 쪽에 더 끌려가요.

**규칙이 찾은 것은 대체로 맞지만, 규칙을 만들 때 생각하지 못한 표현은 놓쳐요.** 형식이 정해진 정보는 규칙으로 대부분 찾을 수 있었어요. 기분은 단어에 드러난 만큼만 알 수 있었어요.

## 실행하기

[uv](https://docs.astral.sh/uv/getting-started/installation/)만 있으면 돼요. 없다면 `pip install uv`로 설치할 수 있어요.

```bash
cd 02_Advanced/A4-2
uv sync --locked
uv run python main.py --text "이 식당은 정말 맛있지 않았어요"
```

- `uv sync`는 Python 3.12와 라이브러리를 이 폴더의 `.venv`에 설치해요. 처음 한 번은 내려받는 데 시간이 걸리고, 약 340MB를 차지해요.
- 위 명령의 결과는 이렇게 나와요.

```text
=== 감성 분석 과정 ===
문장: "이 식당은 정말 맛있지 않았어요"

1. 토큰화: [이, 식당, 은, 정말, 맛있, 지, 않았어요]
2. 감성 단어 탐지: 맛있(+2)
3. 부정어 탐지: '않' → 실제 배율 맛있: ×-1
4. 강조어 탐지: '정말' → 강도 ×1.5

계산: (+2) × (-1) × 1.5 = -3
최종 판정: 부정
```

다른 문장도 같은 방식으로 넣어 볼 수 있어요.

```bash
uv run python main.py --text "문의: support@example.com, 전화 02-0000-0002 일시: 2024년 3월 15일, 참가비: 50,000원"
```

```text
=== 정보 추출 결과 ===
추출 결과:
- 이메일: support@example.com
- 전화: 02-0000-0002
- 날짜: 2024-03-15 (정규화, 원문 '2024년 3월 15일')
- 금액: 50000 (원, 정규화)
```

**전체 평가 다시 재기:** `uv run python -m src.run_all`을 실행하면 평가와 보너스 실험을 모두 다시 해서 `outputs/`에 저장해요. 1~2분 걸리고, 처음 실행할 때 NSMC(약 19MB)와 KNU 감성사전(약 1MB)을 `data/downloads/`로 내려받아요.

**uv 없이 실행:** `pip install -r requirements.txt`로 설치한 뒤, 위 명령의 `uv run python`을 `python`으로 바꾸세요.

**노트북 실행:** VS Code나 Jupyter에서 노트북을 열고, 커널을 `.venv`의 Python으로 고른 뒤 **커널 재시작 후 전체 실행**을 누르세요.

## 처리 흐름

문장 하나가 아래 순서로 처리돼요.

```text
1. 값 찾기        정규식으로 이메일, 전화번호, 날짜, 금액, URL 후보를 찾는다
2. 값 다듬기      실제로 있는 날짜인지 확인하고 2024-03-15처럼 형식을 통일한다
3. 찾은 곳 가리기  찾은 값을 □로 바꿔 날짜 속 숫자나 마침표가 감성 계산을 방해하지 않게 한다
4. 단어 점수 찾기  감성 사전에 있는 단어의 점수를 찾는다
5. 점수 고치기    부정어와 강조어를 반영해 점수를 곱한다
6. 판정          모두 더해 0보다 크면 긍정, 작으면 부정으로 판정한다
```

찾기는 [`src/patterns.py`](src/patterns.py), 다듬기는 [`src/normalize.py`](src/normalize.py), 감성 계산은 [`src/sentiment.py`](src/sentiment.py)에 있어요. 감성 단어와 부정어, 강조어는 [`data/lexicon/`](data/lexicon/)의 표에 있어서 코드를 고치지 않고 추가할 수 있어요.

## 규칙은 이렇게 동작해요

### 정보 추출

| 찾는 값 | 찾을 수 있는 표기 | 이렇게 통일해요 |
| --- | --- | --- |
| 이메일 | `user@example.com`, `user.name@sub.example.com` | 도메인만 소문자로 |
| 전화번호 | `010-0000-0001`, `02-000-0001`, `01000000001`, `+82 10-…` | `010-0000-0001` 형식으로 |
| 날짜 | `2024년 1월 15일`, `2024/01/15`, `24.12.25`, `3월 15일` | `2024-01-15` 형식으로 |
| 금액 | `10,000원`, `1억 2천만원`, `$100`, `오천원` | 정수로. 원화는 원, 달러는 센트 단위 |
| URL | `https://…?q=v`, `www.naver.com` | 앞부분을 소문자로, `www.`만 있으면 `http://`를 붙여서 |

정규식은 **모양이 맞는 후보**만 찾아요. 2월 30일처럼 모양은 맞지만 없는 날짜는 코드가 달력으로 확인해서 버려요. 값이 서로 겹치면 더 긴 쪽을 택해요.

### 감성 점수

단어마다 -3(매우 나쁨)부터 +3(매우 좋음)까지 점수를 적어 두었어요. `좋`은 +2, `최악`은 -3이에요. 직접 만든 사전에는 394개가 있고, 그중 92개는 `발연기`, `불친절하`처럼 영화나 고객 응대에서 자주 쓰는 말이에요. 찾은 단어의 점수에 아래 규칙을 곱한 뒤 모두 더해요.

| 규칙 | 하는 일 | 예 |
| --- | --- | --- |
| 부정어 | 점수를 뒤집어요 (× -1) | `좋지 않다`: (+2) × (-1) = -2 |
| 강조어 | 점수를 키워요 (× 1.2~1.5) | `정말 좋다`: (+2) × 1.5 = +3 |
| 약화어 | 점수를 줄여요 (× 0.5) | `좀 별로`: (-2) × 0.5 = -1 |
| 이중부정 | 부정어 수만큼 뒤집어 원래대로 돌아와요 | `재미있지 않을 수 없다`: (+2) × (-1) × (-1) = +2 |

**점수가 0이면?** 단서가 없거나 긍정과 부정이 상쇄됐다는 뜻이고, 중립이라는 뜻은 아니에요. 이때는 기본값인 부정으로 판정해요. 개발용 리뷰에서 0점 리뷰의 긍정 비율이 0.43으로 절반보다 낮았기 때문이에요.

<details>
<summary>부정어와 강조어의 범위, 확장 규칙</summary>

부정어와 강조어는 아무 단어에나 붙지 않아요.

- **강조어와 약화어:** 감성어 앞, 같은 절 안, 2어절 이내에서만 적용해요.
- **앞에 오는 부정어(안, 못):** 같은 어절에 붙었거나 바로 앞 어절일 때 적용해요.
- **뒤에 오는 부정어(않, 없, 아니 등):** 감성어 뒤, 같은 절 안, 3어절 이내에서 다음 감성어가 나오기 전까지 적용해요. `좋지 않고 재미없다`에서 `않`이 `재미없`까지 뒤집으면 안 되기 때문이에요.

미션 필수 범위 밖에서 개발용 리뷰를 보고 네 가지 규칙을 더 넣었어요. `--rules required`로 끌 수 있어요.

1. **이모티콘:** 같은 글자 반복은 2개로 줄여 비교해요. `ㅋㅋㅋㅋ`는 `ㅋㅋ`로 봐요.
2. **대조:** `지만`, `하지만`, `근데` 앞 절은 × 0.5, 뒤 절은 × 1.5를 해요. 뒤쪽 말이 더 중요한 경우가 많기 때문이에요.
3. **꾸밀 말이 없는 부정어:** `이건 아니다`처럼 감성어가 없으면 -1을 줘요.
4. **평점 언급:** `1점`, `별 한 개`는 -2, `10점`은 +2를 줘요. `10점 만점에`는 제외해요.

</details>

### 감성 분석

규칙을 더할 때마다 시험용 리뷰 1,000건에서 정확도가 어떻게 바뀌는지 쟀어요.

| 단계 | 정확도 | 점수가 0인 리뷰 |
| --- | ---: | ---: |
| 사전 점수만 더하기 | 71.9% | 404건 |
| + 부정어, 강조어, 이중부정 (미션 필수) | **73.3%** | 397건 |
| + 확장 규칙 4가지 (최종) | **76.2%** | 264건 |

부정어와 강조어를 더한 효과가 작아 보이는 이유는 두 가지예요. 부정 표현이 든 리뷰가 많지 않고, 강조어는 부호가 아니라 크기만 바꾸기 때문이에요. 그래서 해당 문장만 모아 따로 쟀어요.

| 확인한 것 | 규칙 없음 | 필수 규칙 |
| --- | ---: | ---: |
| 시험용 리뷰 중 부정어가 작동한 72건의 정확도 | 50.0% | **68.1%** |
| 직접 쓴 부정 문장 18개의 정확도 | 0% | **94.4%** |
| 강조어 쌍 16개 중 강조한 쪽의 점수 크기가 더 큰 쌍 | 0개 | **15개** |

**혼동 행렬(최종 규칙, 시험용).** 부정 리뷰 500건 중 437건, 긍정 리뷰 500건 중 325건을 맞혔어요. 긍정을 많이 놓친 이유는 단서가 없는 리뷰를 모두 부정으로 판정하기 때문이에요.

| H G + 꾸밀 말 없는 부정어 | 0.800 | 0.757 | 0.753 | 278 |
| **I H + 평점 언급 (최종)** | 0.806 | **0.762** | **0.759** | 264 |

- **95% 신뢰구간:** 리뷰 1,000건으로 잰 값이라 표본에 따라 흔들려요. 표본을 다시 뽑아 계산한 구간은 A 69.0~74.6%, E 70.5~75.9%, I 73.4~78.8%예요.
- **차이가 우연일까?(McNemar 검정):** 같은 리뷰에서 한쪽만 맞힌 수를 비교해요. A→E는 16 대 30(p = 0.054)으로 경계선이고, E→I는 19 대 48(p = 0.0005)로 우연이라 보기 어려워요.
- **이중부정만 따로:** 직접 쓴 이중부정 8문장은 부정어를 한 번만 뒤집는 C단계에서 전부 틀리고(0%), 개수만큼 뒤집는 E단계에서 전부 맞아요(100%).

</details>

## 규칙으로 언어를 정의할 수 있을까?

**형식이 정해진 말은 대부분 할 수 있었어요.** 이메일이나 날짜는 F1 0.906까지 왔고, 남은 문제는 한글 숫자나 `만원 버스` 같은 경계 사례예요. **뜻과 태도는 일부만 할 수 있었어요.** 단어에 드러난 감성으로 76.2%까지 왔지만, 나머지는 묘사, 반어, 맥락이라서 규칙을 더해도 잡기 어려워요.

| | 이번 결과로 본 근거 |
| --- | --- |
| **장점: 잡은 것은 대체로 맞아요** | 정보 추출 정밀도 0.939 |
| **장점: 이유를 설명할 수 있어요** | 모든 판정이 `(+2) × (-1) × 1.5 = -3` 같은 계산으로 남아요 |
| **장점: 학습 데이터 없이 시작해요** | 학습 리뷰 10건이면 TF-IDF는 54.1%, 규칙은 76.2%예요 |
| **단점: 놓치는 것이 많아요** | 리뷰의 26%(264건)에서 단서를 찾지 못했어요 |
| **단점: 고치기 어려워요** | 한 곳을 고치면 다른 곳이 깨져요. URL 조사를 떼자 한글 주소가 잘렸어요 |
| **단점: 글자 너머를 못 봐요** | 반어와 감성의 대상은 단어 규칙으로 잡기 어려워요 |

**언제 무엇을 쓸까?**

| 상황 | 알맞은 쪽 |
| --- | --- |
| 연락처, 날짜, 금액처럼 형식이 정해진 값 찾기 | 규칙 |
| 정답 달린 데이터가 거의 없거나 판정 이유를 설명해야 할 때 | 규칙, 또는 규칙과 통계 함께 쓰기 |
| 정답 달린 데이터가 수천 건 이상이고 표현이 다양할 때 | 통계. 이번 실험에서는 약 3,000건부터 규칙을 넘었어요 |

**이렇게 고칠 수 있어요.**

1. **형태소 분석기 쓰기:** `소망합니다`의 `망합` 같은 오탐을 줄일 수 있어요.
2. **관용구 등록하기:** `잊을 수 없는`처럼 칭찬하는 표현을 사전에 넣어요.
3. **단서 없는 문장은 통계 모델에 맡기기:** 0점 리뷰를 무조건 부정으로 판정하지 않게 돼요.
4. **한글 숫자를 먼저 바꾸기:** `공일공`을 `010`으로 바꾼 뒤 같은 패턴을 써요.
5. **앞뒤 단어 보기:** `만원 버스`의 `버스`처럼 주변 말로 뜻을 가려요.

<details>
<summary>보너스 2: 규칙과 통계(TF-IDF) 비교</summary>

**TF-IDF**는 글을 숫자로 바꾸는 통계 방법이에요. 여기서는 글자 1~3개 조각의 TF-IDF에 로지스틱 회귀를 붙여, 같은 시험용 리뷰로 규칙과 비교했어요. 학습 리뷰 수를 바꿔 가며 표본을 여러 번 뽑은 평균이에요.

![학습 리뷰 수에 따른 TF-IDF와 규칙의 정확도.](outputs/rule_vs_tfidf.png)

| 학습 리뷰 수 | TF-IDF | TF-IDF + 규칙 점수 | 규칙(최종) |
| ---: | ---: | ---: | ---: |
| 10 | 54.1% | 74.7% | 76.2% |
| 100 | 64.0% | 76.0% | 76.2% |
| 1,000 | 74.0% | 78.1% | 76.2% |
| 3,000 | **77.5%** | 79.9% | 76.2% |
| 10,000 | 80.5% | **81.3%** | 76.2% |

- **데이터가 적으면** 규칙이 훨씬 나아요. 학습 리뷰 10건으로는 기본 단서조차 배우지 못해요.
- **약 3,000건부터** TF-IDF가 규칙을 넘어요. 다만 이번 데이터에서 나온 수치예요.
- **둘을 합치면** 모든 크기에서 TF-IDF 단독보다 높아요. 학습 리뷰 100건 이하에서는 규칙 단독보다 낮아요.
- **규칙도 공짜는 아니에요.** 사전과 규칙을 만들려고 리뷰 1,000건을 읽었어요. 대신 판정 이유를 설명할 수 있어요.

</details>

<details>
<summary>보너스 3: 대상별 감성 분석</summary>

`음식은 맛있는데 가격이 비싸요`를 맛은 긍정, 가격은 부정으로 나눠 판단해요. `--aspect`로 실행해요.

1. 문장부호와 `지만`, `는데` 같은 말로 절을 나눠요.
2. 맛, 가격, 배송처럼 미리 정한 속성어를 찾아요.
3. 절마다 감성을 계산해요. `가격이 싸다`처럼 대상에 따라 뜻이 정해지는 말도 처리해요.
4. 감성어를 앞에 나온 가장 가까운 속성에 붙여요.

| 방식 | 정밀도 | 재현율 | F1 |
| --- | ---: | ---: | ---: |
| 문장 전체 판정을 모든 속성에 붙이기 | 0.677 | 0.603 | 0.638 |
| **속성별로 나눠 판단하기** | **0.970** | **0.877** | **0.921** |

직접 쓴 48문장(정답 73쌍) 결과예요. 틀린 8문장 중 6문장은 `식다`, `무심하다` 같은 말이 사전에 없어서 틀렸어요.

</details>
