# A4-2 HTML 학습 자료

`a4-2.html` 하나를 브라우저에서 열면 된다. 글꼴(Google Fonts)을 빼면 인터넷 없이 동작한다. 오프라인에서는 시스템 글꼴로 대체된다. 휴대폰 폭(375px)에서도 가로 넘침 없이 읽을 수 있고, 라이트·다크 테마를 지원한다.

## Python 계산 실습

[계산 실습 노트북](../notebooks/rules_walkthrough.ipynb)은 정규식 후보·그룹·좌표에서 Entity까지,
사전 Hit에서 감성 점수까지 작은 사례를 펼친 뒤 전체 평가·보너스로 연결한다.
`uv sync --group dev` 후 `uv run --group dev python tools/build_learning_notebook.py --execute`로
새 커널 실행·재생성한다. 기존 outputs는 보존한다.

HTML의 조작 기능과 Python 자료구조 확인은 역할이 다르다. 노트북 첫 계산 후 아래 HTML 실험실에서
규칙을 바꿔 예상과 결과를 비교하면 좋다. 점수 0은 단서 없음뿐 아니라 기여 상쇄도 포함한다.
이중부정 스위치에 따라 실제 반전 배율이 달라지며 해설은 그 실제 배율을 표시한다.

## 학습 순서

완성된 파이프라인을 먼저 써 보고 부품으로 내려가는 탑다운 순서다.

1. **큰 그림**
   - 00장에 고객 문의 문장을 넣어 본다. 추출, 마스킹, 감성 계산 과정, 속성별 감성이 한 화면에 나온다. 규칙 스위치를 끄고 켜며 결과가 어떻게 바뀌는지 본다.
   - 01장에서 흐름과 결과 요약을 본다.
2. **정규식**
   - 02장 문법 카드를 시험대에 올려 그룹 값을 확인한다.
   - 03장 패턴 실험실에서 패턴을 직접 고쳐 정밀도·재현율이 어떻게 움직이는지 본다. 장마다 도전 과제가 있다.
3. **검증과 정규화**: 04장에서 한글 수사 금액 파서의 단계별 상태와 날짜 검증을 본다.
4. **감성 규칙**
   - 05장: 어간 하나로 활용형을 맞추는 방법(받침 확장, 변이 생성)과 사전 전체를 본다.
   - 06장: 표적 문장 40개 × 규칙 9단계 표에서 칸을 눌러 계산 과정을 비교한다.
5. **평가와 실패**
   - 07장: NSMC 2,000건을 브라우저에서 다시 분석하며 규칙별 정확도를 잰다.
   - 08장: 추출 실패와 감성 오분류의 원인을 본다.
6. **보너스와 정리**
   - 09장: 마스킹, 규칙 vs TF-IDF 학습 곡선, 속성 분석기.
   - 10장: 핵심 질문에 대한 답.
   - 11장: 과제 목표 5문항으로 스스로 점검한다.

## 포함 내용

- 위젯 13개
  - 통합 파이프라인(규칙 스위치 7개와 묶음 설정 3개)
  - 정규식 시험대
  - 패턴 실험실(80문장 재평가)
  - 금액 파서 단계표
  - 날짜 검증
  - 활용 변이 생성
  - 어절 사전 찾기
  - 사전 둘러보기(검색·분야별)
  - 규칙 표적 문장 표
  - NSMC 재평가(혼동 행렬, 오분류·단서 없음·부정어 작동 목록)
  - 오분류 사례 탐색
  - 마스킹 결과표
  - 속성 분석기(연결 방식 2가지)
- 차트 2개: 규칙 단계별 정확도(dev·test)와 규칙 vs TF-IDF 학습 곡선. 둘 다 마우스를 올리면 수치가 나온다.
- 표: 추출 패턴별 P/R/F1, bootstrap 신뢰구간, McNemar 검정, 사전 비교, 부정어 작동 리뷰 비교, TF-IDF 학습 곡선

리뷰 본문은 NSMC(CC0)에서 왔다. 실명과 비속어가 들어 있을 수 있다. KNU 감성사전은 저장소에 라이선스 표기가 없어서 파일에 넣지 않았다. 사전 비교표의 KNU 수치만 Python 실행 결과에서 옮겼다.

## 작성 당시 검증

이 HTML은 작성 당시의 소스·결과로 한 번 만든 학습 자료다. 생성 도구와 템플릿은 정리했고, 아래 표는 작성 당시 확인한 범위다. 현재 Python 계산·평가의 재현과 새 노트북 실행은 위 명령으로 확인한다.

`uv run --group dev python tools/verify_learning_flow.py`는 실행 노트북과 생성기의 셀·ID,
별도 JS와 HTML 내 스크립트, 소스 발췌 15개를 대조한다. Node.js가 필요하다.
감성은 dev/test 2,000건 + 고정 난수로 뽑은 pool 3,000건 + 표적·경계 45문장에 규칙 9단계를 적용한다.
추출 80문장·마스킹 20문장·속성 48문장×연결 2방식도 Python과 JS를 비교한다.
문자열 위치는 Python 코드 포인트와 JS UTF-16 코드 단위의 차이를 환산해 대조한다.
이 검사는 브라우저 화면·조작 검증과 별개다.

`engine.js`(Python 규칙 엔진을 옮긴 것)와 `app.js`(화면)는 HTML에 들어간 스크립트의 원본이다.

HTML 안의 엔진을 Node.js에서 실행해 Python 구현과 비교했다.

| 항목 | 내용 | 결과 |
| --- | --- | --- |
| 감성 | NSMC dev·test 2,000건 + pool 무작위 3,000건 + 표적 문장 72개 × 규칙 9단계의 점수(오차 1e-9)와 판정 | 45,648건 모두 일치 |
| 토큰 조각 | 같은 5,072문장의 최종 설정 토큰화 결과 | 모두 일치 |
| 추출 | 추출 테스트 80문장 + 위 리뷰 전부의 (유형, 원문, 정규화 값) | 5,152문장 모두 일치 |
| 마스킹 | 마스킹 테스트 20문장 + 추출 테스트 80문장 | 100문장 모두 일치 |
| 속성 | 속성 테스트 48문장 + test 1,000건 × 연결 방식 2가지 | 2,096건 모두 일치 |
| 구조 | 스크립트·링크가 참조하는 id가 모두 있는가 | 94개 모두 있음 |

JS 엔진을 옮기면서 Python 쪽 비결정성 하나를 찾아 고쳤다. 속성 분석에서 문맥 의존어가 두 속성에 걸칠 때 `frozenset` 순회 순서를 따랐는데, 그 순서는 실행마다 바뀔 수 있다. 지금은 정렬해서 순회한다.

화면은 미리보기 브라우저에서 데스크톱 폭(1280px)과 375px 폭, 라이트·다크 테마로 확인했다(가로 넘침 없음, 콘솔 오류 없음). 이는 수동 관찰이고 위 자동 검증과는 별개다.
