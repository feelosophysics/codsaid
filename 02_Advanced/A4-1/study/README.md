# A4-1 HTML 학습 자료

`a4-1.html` 하나를 브라우저에서 열면 된다. 글꼴(Google Fonts)을 빼면 인터넷 없이 동작한다. 오프라인에서는 시스템 글꼴로 대체된다. 휴대폰 폭에서도 읽을 수 있다.

탑다운 순서로 구성했다. 먼저 00장 검색창에서 완성된 검색기를 써 보고, 01장에서 전체 흐름을 본다. 그다음 02 전처리 → 03 TF-IDF → 04 코사인 → 05 분류 → 06 BoW의 한계 순으로 내려간다. 07–09장은 보너스(TF 변형, BM25, 역색인)다. 10장의 질문 5개는 검색 원리를 자신의 말로 설명해 보는 자기 점검용이다. 11장은 각 계산이 들어 있는 소스 위치다.

## 포함 내용

- 전체 4,631건의 단어 빈도 포스팅으로 브라우저에서 다시 계산하는 검색. TF-IDF(TF 변형 4종)와 BM25(k1·b 조절)를 지원하고 방문한 포스팅 수를 보여 준다.
- 전처리 4단계 시각화(입력 글을 고치면 바로 갱신)
- TF-IDF 장난감 계산기(빈도 행렬 → df·idf → 정규화 TF-IDF, 설정 18가지)
- sklearn 대조 13개 설정 표, 실제 코사인 계산 분해
- 혼동 행렬, 범주별 지표, 오분류 8건의 원인 단어 막대
- 두 문장의 BoW 벡터 비교(어순·부정어·동의어·다의어), 한국어 토큰화 예
- TF 변형 비교 차트, BM25 포화 곡선(k1·b 조절)과 민감도 격자, 역색인 포스팅 조회와 벤치마크 차트
- 핵심 함수 16개의 원문과 줄 번호

검색 결과의 발췌는 각 글의 앞 280자이고 이메일·URL은 `[email]`·`[url]`로 가렸다. 본문에 남은 공인·작성자 이름은 그대로 보일 수 있다.

## 재생성과 검증

상위 A4-1 폴더에서:

```powershell
uv run python -m src.run_all                 # outputs/ 갱신(약 5분)
uv run python tools/build_study_guide.py     # a4-1.template.html + 색인 + outputs → a4-1.html
uv run python tools/verify_study_guide.py    # Node.js 필요
```

`a4-1.template.html`이 설명과 화면의 편집 원본이다. build 도구가 현재 코드로 만든 색인·`outputs/*.json`·소스 발췌를 넣는다. 본문 설명문 속 수치 일부(예: 오분류 사례 해설)는 자동 갱신되지 않는다. 데이터나 전처리를 바꾸면 설명도 다시 봐야 한다.

검증 도구는 HTML의 JavaScript를 Node.js에서 실행해 Python 구현과 비교한다.

| 항목 | 내용 | 결과 |
| --- | --- | --- |
| 전처리 | 원본 4,941건 전부의 토큰이 `preprocess()`와 같은가 | 불일치 0건 |
| 검색 | 쿼리 26개 × (TF-IDF 4변형 + BM25 2설정)의 top-5 순위와 점수(오차 1e-9) | 156개 모두 일치 |
| 장난감 계산기 | 18개 설정의 TF-IDF 행렬이 `TfidfVectorizerNP`와 같은가 | 최대 오차 0 |
| 구조 | 스크립트·링크가 참조하는 id가 모두 있는가 | 67개 모두 있음 |

이 검증으로 JS 전처리의 버그 하나를 찾아 고쳤다. 철자 변형 사전을 일반 객체로 조회해서 `constructor`라는 단어가 `Object.prototype` 속성으로 바뀌던 문제다.

화면은 브라우저에서 데스크톱 폭과 375px 폭으로 한 번씩 확인했다(가로 넘침 없음, 콘솔 오류 없음). 이는 수동 관찰이고 자동 검증과는 별개다.
