# 📈 B1-1 보너스 미션 시연 및 무결성 검증 가이드북

본 문서는 프로젝트 최종 발표 및 시연 현장에서 **시간 기반 로그 보존(Retention Policy) 정책(`archive.sh`)**과 **특정 시간 범위 통계 리포트(`report.sh`)** 기능이 실제로 수십 일이 흐르지 않고도 즉시 검증 및 시연될 수 있도록 돕는 실무 가이드북입니다.

> [!IMPORTANT]
> **🛡️ 실 운영 데이터 보존을 위한 비파괴적(Non-destructive) 검증 메커니즘 적용**
> - 본 시연 가이드는 실제 운영 중인 시스템 관제 데이터의 무결성을 안전하게 지키기 위해 **비파괴적 설계**를 엄격히 준수합니다.
> - **멱등한 경로 안전 확보**: `mkdir -p` 명령어를 사용하여, 기존에 이미 수집된 로그 디렉토리나 데이터가 존재한다면 파괴적으로 지우거나(`rm -rf` 등) 포맷하지 않고 파일 시스템 경로만 안전하게 확보 및 보존합니다.
> - **시연 파일 격리**: 실시간 로그 수집 파일인 `monitor.log`에 직접적인 데이터 조작이나 덮어쓰기를 가하지 않기 위해, 시간 기반 압축/삭제 시연은 별도로 격리된 **가상 타겟 파일(`test_history.log`)**을 독립 `touch` 생성하여 수행합니다.
> - **안전한 파일 끝에 이어 쓰기 (`>>` Append)**: 통계 시연 데이터 주입 시에도 기존에 누적되어오던 로그 이력을 지워버리지 않기 위해 단일 꺾쇠(`>`) 덮어쓰기가 아닌 **이중 꺾쇠(`>>`)를 통한 마지막 줄 이어 붙이기**를 강제 적용했습니다.
> - 상세한 데이터 무결성 조치 원리는 [README.md의 트러블슈팅 - 📌 ISSUE 4]에서 직접 확인하실 수 있습니다.

## 💡 1. 핵심 검증 기법의 원리: "시간 여행 트릭"

리눅스의 `find` 명령어에서 사용하는 기간 필터(`-mtime +7` 등)는 파일의 메타데이터에 기록된 **'최종 수정 시각(mtime - Modification Time)'**을 기준으로 동작합니다.

따라서 실제 수십 일을 기다리지 않고도, 파일 시스템의 mtime을 임의의 과거 시점으로 순간이동 시켜주는 **`touch -d` (date 지정)** 명령어를 활용하면 시뮬레이션 환경을 완벽하게 재현할 수 있습니다.

* **7일 경과(압축 대상) 조건 재현:**
  `touch -d "8 days ago" /var/log/agent-app/monitor.log.1`
* **30일 경과(삭제 대상) 조건 재현:**
  `touch -d "31 days ago" /var/log/monitor/agent-app/archive/monitor.log.10.gz`

## 🛠️ 2. [원터치 및 비파괴] 시연용 테스트베드 데이터 자동 생성기

사용자가 수동으로 파일을 한 땀 한 땀 만들고 시간을 위조하는 번거로움을 완전히 소거하기 위해, 아래의 **"원터치 테스트베드 제너레이터"** 스냅샷 코드를 제공합니다. 

이 코드는 실 운영 서버의 데이터를 손상시키지 않고 안전하게 격리된 가상 시뮬레이션 대상을 구성하므로, 운영 서버에서도 안심하고 실행할 수 있습니다.

### 📝 원터치 시연 데이터 빌드 명령어
> [!CAUTION]
> **⚠️ 반드시 `root` 권한을 획득한 터미널에서 실행해 주세요!**
> - 일반 `agent-admin` 계정은 시스템 보안 규정에 따라 `sudoers`에 등록되어 있지 않아 `sudo` 권한을 행사할 수 없습니다 (`agent-admin is not in the sudoers file`).
> - 따라서 `sudo -i` 또는 `su -` 또는 `orb -u root` 등을 활용하여 **`root` 터미널로 완전히 전환한 뒤** 아래 명령어 전체를 복사하여 붙여넣고 실행하셔야 정상적으로 가상 테스트베드가 구축됩니다.
> - bash 셸 환경에서 `!` 느낌표 문자가 쌍따옴표 내부에 있을 때 발생하는 `event not found` 오류를 완벽하게 방지할 수 있도록, 문자열 출력을 안전한 홑따옴표(`'`) 감싸기 구조로 설계했습니다.

```bash
# 1. [안전 확보] 실 운영 데이터 유실 방지(비파괴적) 디렉토리 구조 안전 확보
# mkdir -p 명령어는 해당 경로가 이미 존재하더라도, 기존 데이터를 덮어쓰거나 
# 파괴(rm -rf 등)하지 않고 안전하게 없는 세부 디렉토리만 무해하게 보존/생성합니다.
mkdir -p /var/log/agent-app
mkdir -p /var/log/monitor/agent-app/archive

# ── [시나리오 1용 더미] 압축 및 이동 대상 파일 빌드 (8일 전 생성된 가짜 로그) ──
# 실시간 관제 데이터인 monitor.log에 직접 손을 대지 않고, 시연만을 위해 독립 설계된 
# 가상의 격리 타겟 파일(test_history.log)을 생성하여 실 운영 무결성을 엄격하게 준수합니다.
echo "[2026-05-15 10:00:00] PID:9999 CPU:12.3% MEM:4.5% DISK_USED:20%" > /var/log/agent-app/test_history.log
# 수정 시간을 강제로 8일 전으로 순간 이동시킵니다.
touch -d "8 days ago" /var/log/agent-app/test_history.log

# ── [시나리오 2용 더미] 영구 삭제 대상 파일 빌드 (31일 전 생성된 아카이브) ──
# 30일이 지난 노후화된 백업 파일이 영구 삭제되는 시나리오를 입증하기 위한 격리 더미입니다.
echo "old archive content" | gzip > /var/log/monitor/agent-app/archive/expired_backup.log.gz
# 수정 시간을 강제로 31일 전으로 순간 이동시킵니다.
touch -d "31 days ago" /var/log/monitor/agent-app/archive/expired_backup.log.gz

# ── [시나리오 3용 더미] report.sh 용 5월 20일 특정 시간대 시계열 적재 데이터 주입 ──
# 5월 20일 오전 09:00 ~ 09:03 사이에 분 단위로 자원 스파이크가 튄 로그를 기입합니다.
# 이때 기존에 적재되어 있던 실시간 monitor.log의 역사적 기록이 증발하지 않도록 
# 덮어쓰기(>)가 아닌 추가(>>) 리다이렉션을 사용해 파일 끝에 안전하게 누적 어펜드합니다.
cat >> /var/log/agent-app/monitor.log << 'EOF'
[2026-05-20 09:00:01] PID:5067 CPU:10.5% MEM:5.1% DISK_USED:22%
[2026-05-20 09:01:01] PID:5067 CPU:88.4% MEM:9.8% DISK_USED:22%
[2026-05-20 09:02:01] PID:5067 CPU:55.2% MEM:7.3% DISK_USED:23%
[2026-05-20 09:03:01] PID:5067 CPU:12.1% MEM:5.0% DISK_USED:23%
EOF

# 소유권 정상 주입
chown -R agent-admin:agent-core /var/log/agent-app
chown -R agent-admin:agent-core /var/log/monitor

# 느낌표 event not found 방지를 위해 전체 홑따옴표 처리
echo -e '\n\e[1;32m✅ 시연용 가상 테스트베드가 3초 만에 정교하게 완성되었습니다!\e[0m\n'
```

## 📈 3. 실제 발표용 단계별 시연 시나리오

위의 테스트베드 생성 코드를 구동한 뒤, 참관인(면접관 등) 앞에서 순서대로 스크립트를 작동시켜 실시간 출력을 검증합니다.

### 🎬 시나리오 [1] 7일 경과 파일의 자동 압축 및 아카이브 대피 시연

* **설명:**
  > "저희 시계열 보존 정책 스크립트(`archive.sh`)는 평소 디스크를 점유하는 7일 이상 노후화된 평문 텍스트 로그를 압축하여 시스템 부하가 없는 별도의 콜드 스토리지 아카이브 물리 저장 공간으로 자동 이송시킵니다. 방금 전 8일 전 수정 시간으로 주입한 `test_history.log` 파일의 변화를 보여드리겠습니다."

* **실행 명령어:**
  ```bash
  # 1. 실행 전 대상 폴더의 상태 확인 (평문 텍스트 상태)
  ls -lh /var/log/agent-app/test_history.log
  
  # 2. 보존 스크립트 구동
  sudo -u agent-admin /home/agent-admin/agent-app/bin/archive.sh
  
  # 3. 결과 확인 (원본 로그 디렉토리에서 평문 텍스트가 깨끗이 소거됨을 입증)
  ls -lh /var/log/agent-app/test_history.log 2>/dev/null || echo "-> 원본 파일 대피 소거 완료!"
  
  # 4. 아카이브 보관소에 .gz로 압축되어 이송 완료되었는지 증명
  ls -lh /var/log/monitor/agent-app/archive/test_history.log.gz
  ```

> [!TIP]
> **성공 관전 포인트:** 
> `test_history.log` 파일이 원본 디렉토리에서 안전하게 gzip 압축 처리된 후, `/var/log/monitor/agent-app/archive/` 로 이동 배치되었는지가 시연의 무결성 핵심 포인트입니다.

### 🎬 시나리오 [2] 30일 경과 노후 아카이브의 영구 삭제 시연

* **설명:**
  > "압축된 아카이브 파일 역시 무한히 보존하면 디스크 고갈 위협이 상존합니다. 따라서 법적 증적 한계선인 30일이 경과한 아카이브는 스크립트가 능동적으로 탐지해 안전하게 영구 삭제(Purge)합니다. 방금 생성했던 31일 전 수정 시간의 `expired_backup.log.gz` 파일이 어떻게 관리되는지 입증하겠습니다."

* **실행 명령어:**
  ```bash
  # 1. 실행 전 아카이브 디렉토리 내부 상태 모니터링 (31일 전 가짜 백업 파일 존재 확인)
  ls -lh /var/log/monitor/agent-app/archive/expired_backup.log.gz
  
  # 2. 보존 스크립트 재구동
  sudo -u agent-admin /home/agent-admin/agent-app/bin/archive.sh
  
  # 3. 결과 검증 (30일 경과 아카이브가 깔끔히 영구 파쇄 처리되었는지 증명)
  ls -lh /var/log/monitor/agent-app/archive/expired_backup.log.gz 2>/dev/null || echo "-> 30일 초과 아카이브 완전 영구 파쇄 성공!"
  ```

> [!IMPORTANT]
> **성공 관전 포인트:** 
> `archive.sh` 로그 콘솔 출력 중에 `[3단계] 30일 이상 된 아카이브 파일 삭제 중...` 섹션 하위에 `삭제 중: /var/log/monitor/agent-app/archive/expired_backup.log.gz` 문구가 성공적으로 덤프되고 실제 파일이 소멸되었는지가 핵심입니다.
