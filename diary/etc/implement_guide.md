# Refactoring Guide for Mini-Git Project (v2.0)

본 문서는 Mini-Git 파이썬 프로젝트의 리팩토링을 위한 핵심 가이드라인입니다. antigravity 에이전트는 코드를 수정하거나 제안할 때 반드시 아래의 소프트웨어 엔지니어링 원칙들을 엄격하게 준수해야 합니다.

## 1. Core Philosophy (핵심 철학)
- **Code as Documentation (명세서 같은 코드)**: 코드는 기계가 아닌 '사람'이 읽기 편한 명세서처럼 작성되어야 합니다.
- **명시성(Explicitness) 우대**: 짧고 함축적인 코드보다, 길더라도 의도가 명확하고 흐름이 뚜렷한 코드를 지향합니다.

## 2. Architecture & Design Principles (설계 원칙)
- **단일 책임 원칙 (SRP)**: 모든 함수와 클래스는 오직 하나의 책임(기능)만 가져야 합니다. 여러 기능이 섞여 있다면 반드시 분리하세요.
- **적극적인 클래스(OOP) 활용**: 상태와 행위를 묶는 것이 효과적이거나 모듈화가 필요한 경우, 적극적으로 클래스를 도입하세요.
- **사이드 이펙트 최소화 (No Side Effects)**: 가능하면 순수 함수(Pure Function)로 작성하고, 전역 상태(Global State)를 변경하는 것을 극도로 지양하세요.

## 3. Data Flow & Pipeline (데이터 처리 흐름)
모든 주요 기능과 메서드는 다음 3단계의 흐름을 명확히 분리하여 구현하세요.
1. **Data Refinement (데이터 정제)**: 입력된 데이터를 다루기 쉬운 형태로 가공합니다.
2. **Validation (유효성 검사)**: 정제된 데이터의 결함 여부를 검증합니다.
3. **Logic Execution (비즈니스 로직 실행)**: 검증이 완료된 안전한 데이터로만 핵심 로직을 수행합니다.

## 4. Coding Standard & Syntax Constraints (엄격한 코딩 컨벤션)
- **타입 힌트 (Type Hinting) 필수**: 모든 함수 파라미터와 반환값, 주요 변수에는 반드시 Python `typing` 모듈을 활용하여 타입을 명시하세요. (예: `-> list[str]:`)
- **Guard Clauses (보호 구문) / Early Return**: 예외 처리나 비정상 종료 조건은 함수의 **최상단에 배치**하여 들여쓰기 깊이(Depth)를 최소화하세요.
- **명확한 네이밍 (Intention-Revealing Names)**: `data`, `res`, `tmp` 같은 모호한 변수명은 금지합니다. 변수는 명사형, 함수는 동사형으로 목적이 명확히 드러나게 작성하세요.
- **명확한 분기 처리**: 제어 흐름을 명확히 하기 위해 `if`, `elif`, `else`를 생략 없이 명시적으로 사용하세요.

## 5. Anti-Patterns to Avoid (절대 금지 사항)
- **매직 스트링/매직 넘버 금지**: 하드코딩된 문자열이나 숫자는 금지합니다. 반드시 `Enum` 클래스나 상수를 모아둔 텍스트 전용 클래스로 분리하여 관리하세요.
- **삼항 연산자(Ternary Operator) 최소화**: 가독성을 해치는 복잡한 삼항 연산자 대신 명시적인 `if-else` 구문을 사용하세요.
- **리스트 컴프리헨션(List Comprehension) 지양**: 복잡한 로직이 들어간 컴프리헨션은 가독성을 낮추므로, 명시적인 `for` 루프를 우선적으로 사용하세요.
- **포괄적 예외 처리 금지**: `except Exception:`과 같이 뭉뚱그려서 에러를 잡지 말고, `except FileNotFoundError:`처럼 구체적인 예외를 명시하세요.
