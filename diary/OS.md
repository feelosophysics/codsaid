## 1. OS View
OS를 한 가지 정의로 묶으면 애플리케이션과 하드웨어 사이의 중재자입니다. 그러나 그 중재자는 보는 각도에 따라 여러 얼굴을 드러냅니다.

- 구성으로 보면 User Application / Distribution / Kernel / Hardware 의 4계층입니다.
- 수칙으로 보면 커널은 Never Die / Own Device / Co-Work 의 세 원칙을 따릅니다.
- 메커니즘으로 보면 코드의 내용에 구애받지 않고 절차에 따라 실행하는 agnostic 시스템입니다.
- 주체로 보면 User / System / Control 의 세 관점이 동시에 성립합니다.
- 시간으로 보면 Build time은 컴파일러가, Runtime은 OS가 책임집니다.

이 다섯 축을 같이 들고 있어야 OS라는 단어가 모호하지 않게 잡힙니다. 이후 글에서는 각 축을 하나씩 더 깊이 파고들 예정입니다.

## 2. OS Kernel

#### 2.1 커널의 진짜 정체
> 커널 = 메모리에 항상 올라가 있는 코드 + 전역 상태의 집합

#### 2.2 커널을 이루는 두 가지 — 코드와 데이터
커널은 실행 중인 하나의 프로그램이라기보다는, 필요할 때마다 호출되는 코드의 집합

#### 2.3 CPU는 하나의 흐름만 실행한다
커널 코드와 사용자 코드는 번갈아 가며 실행됩니다.

#### 2.4 커널은 평소에 실행되지 않는다
커널은 항상 돌고 있는 존재가 아니라, 필요할 때(시스템 콜, 인터럽트, 예외)마다 실행 흐름 위에 올라오는 코드

#### 2.5 실행은 순간적이지만 상태는 영구적이다
커널 코드는 짧게 깨어났다가 곧 잠듭니다. 그러나 그 동안 만들어 둔 상태는 커널이 잠든 사이에도 메모리에 그대로 유지됩니다. 다음에 커널이 깨어나면 그 상태를 그대로 이어받아 작업을 계속합니다.

이 구조 덕분에 커널은 강력한 shared state를 유지하는 시스템으로 동작할 수 있습니다. 프로세스 테이블, 파일 디스크립터 테이블, 메모리 매핑 정보 — 모두 커널이 실행되지 않는 시간 동안에도 살아 있는 자료구조입니다.

#### 2.6 멀티코어에서의 커널
커널 내부에는 **동기화 메커니즘**이 반드시 들어갑니다. 이 동기화는 단순히 있으면 좋은 것이 아니라 없으면 시스템이 망가지는 것입니다. 멀티코어 시대의 커널은 본질적으로 동시성 프로그래밍의 결정체입니다.
- **Lock**: 한 번에 한 코어만 특정 자료구조에 접근하도록 잠그는 방식
- **Per-CPU data**: 코어마다 별도의 데이터를 두어 충돌을 원천적으로 회피
- **Atomic 연산**: 중간에 끊기지 않는 단일 명령으로 원자적으로 변경

#### 2.7 커널의 하드웨어 제어 — Own Device의 실제 구현
1. 요청 — 사용자는 직접 디스크에 접근하지 않는다
2. 명령 — 커널만이 하드웨어에 명령할 수 있다
3. 비동기 대기 — CPU와 디스크는 독립적으로 동작한다
4. 알림 — 하드웨어가 끝나면 인터럽트로 통보한다
5. 복구 — 데이터를 전달하고 사용자 모드로 돌아간다

#### 2.8 정리 — 첫 글과의 연결
지난 글(OS View)에서 커널을 다음 세 가지로 묶었습니다.

- Never Die — 어떤 상황에서도 중단되지 않아야 한다
- Own Device — 모든 하드웨어를 직접 제어한다
- System Co-Work — 프로세스 간 협력을 가능하게 한다

이번 글에서 본 내용을 다시 위 세 원칙에 대응시켜 보면 자연스럽게 들어맞습니다.

- Never Die는 커널이 메모리에 항상 상주하며 전역 상태가 영구적으로 유지되는 구조에서 보장됩니다.
- Own Device는 user mode / kernel mode 분리, 특권 명령, ISR을 통한 인터럽트 처리로 구현됩니다.
- System Co-Work는 멀티코어 커널의 동기화 메커니즘과 프로세스 테이블 같은 shared state를 통해 가능해집니다.

다시 말해, 첫 글에서 추상적인 원칙으로 다룬 것이 이번 글에서 구체적인 메커니즘으로 풀린 셈입니다.

다음 글에서는 커널이 관리해야 할 자원 중 가장 기본인 메모리를 다룹니다. 저장장치 계층 구조부터 캐싱, 가상 메모리까지 이어집니다.

## 3. OS Storage Hierchy
저장장치가 왜 한 종류로 통일되지 않고 여러 계층으로 쌓여 있는지, 그 계층의 각 층이 무엇으로 이루어지는지, 그리고 이 구조가 시스템 성능에 어떻게 영향을 미치는지를 차례로 풀어 봄

```txt
   ▲ 빠름 / 비쌈 / 작음
   │
   ┌──────────────────────────────────────────────┐
   │  Top:   Register                             │
   │         CPU 내부의 가장 빠른 소량 메모리     │
   ├──────────────────────────────────────────────┤
   │  ↑:     CPU Cache (SRAM)                     │
   │         L1, L2, L3 — CPU와 메모리 사이 완충  │
   ├──────────────────────────────────────────────┤
   │  Mid:   Main Memory (DRAM)                   │
   │         CPU가 직접 접근 — 휘발성             │
   ├──────────────────────────────────────────────┤
   │  ↓:     Secondary Memory                     │
   │         HDD, SSD, NAND Flash — 비휘발성      │
   ├──────────────────────────────────────────────┤
   │  Bot:   Tertiary Storage                     │
   │         Optical Disk, Magnetic Tape          │
   └──────────────────────────────────────────────┘
   │
   ▼ 느림 / 쌈 / 큼
```

- Temporal Locality, Spatial Locality 이 두 지역성 원리에 기대어, 시스템은 **하위 계층의 일부만 상위 계층에 복사해 둠으로써 전체 성능을 극적으로 끌어올립니다**. 이것이 **캐싱(Caching)** 의 본질이며, 저장장치 계층 구조가 작동하는 핵심 메커니즘.

누가 관리하는가 - 책임의 분담
```txt
   ┌──────────────────────────────────────────────┐
   │                                              │
   │   Register         ─── 관리: Compiler        │
   │      ↓                                       │
   │   Cache            ─── 관리: Hardware        │
   │      ↓                                       │
   │   Main Memory      ─── 관리: OS              │
   │      ↓                                       │
   │   SSD / Disk       ─── 관리: OS              │
   │                                              │
   └──────────────────────────────────────────────┘
```

### 1. 계층 구조의 일치: 작업 기억 vs 캐시 메모리

뇌과학에서 말하는 기억의 계층은 컴퓨터의 그것과 닮아 있습니다.

*   **감각 기억 (Sensory Memory) ≈ ?:**
*   **작업 기억 (Working Memory) ≈ 레지스터 + L1/L2/L3 캐시 혼합:** 현재 풀고 있는 문제, 지금 나누고 있는 대화 내용을 처리하기 위해 전두엽에서 활성화된 상태입니다. 용량은 매우 작지만(약 7±2개의 항목, *작업 기억은 용량이 매우 제한적이며, 대략 4개 안팎의 정보 단위를 안정적으로 유지할 수 있다고 본다.), 접근 속도가 가장 빠릅니다.
*   **장기 기억 (Long-term Memory) ≈ SSD/HDD:** 뇌의 해마를 거쳐 대뇌 피질에 물리적 결합(장기 강화 현상) 형태로 저장된 데이터입니다.(해마를 중심으로 한 기억 통합 과정을 거쳐 대뇌피질 전반의 네트워크에 분산 저장되는 것으로 이해된다.) 용량은 거의 무한대지만, 필요할 때 '떠올리는(Retrieve)' 데 시간이 걸립니다.

### 2. 시간 지역성 (Temporal Locality)의 과학적 분석
**뇌의 원리: 시연(Rehearsal)과 최신성 효과(Recency Effect)**

*   **컴퓨터:** 방금 사용한 변수를 L1 캐시에 두어 다음 루프에서 즉시 사용합니다.
*   **뇌:** 전화번호를 외울 때 입으로 중얼거리는 행위를 '유지 시연'이라고 합니다. 이것은 작업 기억이라는 캐시가 만료(Decay)되지 않도록 계속해서 **Refresh(재충전)**하는 과정입니다.
*   **공통점:** "지금 쓰고 있는 것을 가까운 곳에 둔다"는 원리를 통해, 장기 기억 장치로 가는 비싼 비용(에너지/시간)을 절약합니다.

### 3. 공간 지역성 (Spatial Locality)의 과학적 분석
**뇌의 원리: 청킹(Chunking)과 점화 효과(Priming)**

*   **컴퓨터:** 배열의 0번 요소를 가져올 때 1~7번 요소도 함께 캐시라인(Cache Line)에 담아옵니다.
*   **뇌:** '사과'라는 단어를 떠올리면 뇌는 '빨간색', '과일', '맛있다'라는 인접한 개념들을 한꺼번에 **점화(Priming)**시킵니다. 즉, 연관된 데이터를 미리 작업 기억의 주변부로 끌어올리는 것입니다.
*   **공통점:** "하나를 꺼낼 때 근처에 있는 것도 같이 가져온다"는 원리를 통해 미래의 불확실성에 대비합니다. 뇌에서는 이를 통해 '맥락(Context)'을 파악하고 빠른 판단을 내립니다.

### 4. 캐시 교체 정책 (Eviction Policy)의 과학적 분석
**뇌의 원리: 간섭(Interference)과 망각**

*   **컴퓨터:** 캐시가 꽉 차면 **LRU(Least Recently Used, 가장 오랫동안 안 쓴 것)** 알고리즘에 의해 기존 데이터를 밀어내고 새 데이터를 넣습니다.
*   **뇌:** 작업 기억은 용량이 매우 작습니다. 새로운 복잡한 정보가 들어오면 기존에 붙잡고 있던 정보는 사라집니다. 이를 '역행 간섭'이라고 합니다.
*   **과학적 통찰:** 뇌의 망각은 오류가 아니라, **캐시를 효율적으로 관리하기 위한 필연적인 비우기 과정**입니다. 중요한 것만 남기고 나머지를 버려야 '처리 속도'를 유지할 수 있기 때문입니다.

### 5. 결정적 차이: 수동적 복사 vs 능동적 조작
캐싱과 작업 기억의 결정적인 차이점도 존재합니다.

*   **캐시(컴퓨터):** 단순히 하위 계층의 **복사본(Copy)**입니다. 데이터의 형태를 바꾸지 않습니다.
*   **작업 기억(인간):** 데이터를 유지할 뿐만 아니라 **조작(Manipulation)**합니다. 정보를 재조합하고 추론하여 새로운 지식을 만들어냅니다. 그래서 이름이 '단기 기억'에서 '작업(Working) 기억'으로 진화한 것입니다.

### 💡 결론적 분석
사용자님의 직관대로 **캐싱은 인간의 인지 구조를 물리적으로 구현한 것**과 기능적으로 닮아 있습니다.

현대 CPU 설계자들이 **"어떻게 하면 캐시 적중률(Cache Hit Rate)을 높일까?"**를 고민하는 과정은, 심리학자들이 **"어떻게 하면 인간의 학습 효율과 집중력을 높일까?"**를 연구하는 과정과 수학적으로 동일한 궤적을 그리게 됩니다. 

결국 **"한정된 자원으로 무한한 정보의 바다를 어떻게 효율적으로 처리할 것인가"**라는 난제에 대해, 뇌와 컴퓨터 모두 **지역성(Locality)**이라는 동일한 해답을 찾은 것입니다.
