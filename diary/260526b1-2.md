[오늘의 느낀 점]
- 가상 메모리는, 은행의 지급준비율과 비슷하네.
- 현대 운영체제에서 프로그램을 실행할 때 첫 번째 명령어를 읽는 순간부터 무조건 페이지 폴트(Page Fault)가 발생한다. 이를 전문 용어로 **'요구 페이징(Demand Paging)'**이라고 하고, 처음 발생하는 페이지 폴트는 특히 **'메이저(Major) 페이지 폴트'**라고 부름. / 성능을 극도로 중시하는 환경에서는 이를 우회하기도 함.(예측 로딩Prefetching / mlock: 실시간 제어 시스템이나 고성능 DB에서 이 시스템 콜을 사용할 수 있음.)
- 리눅스 2.6.23 커널부터 도입되어 현재까지 리눅스의 표준 데스크톱/서버 스케줄러로 군림하고 있는 알고리즘인 CFS(Completely Fair Scheduler)라는 게 있구나. 가상 실행시간(vruntime) 개념이 있구나.
- 하드웨어 Watchdog도 있네.
- 병렬처리:
    1. 리눅스에서 병렬 실행 방법은 전통적으로 `fork()` 시스템 콜을 이용함. 문제는, 프로세스 간 데이터를 주고받으려면 파이프, 공유메모리 등 무겁고 느린 Inter-Process Commuication 기법을 써야 함.
    2. 대안으로, 하나의 프로세스 안에서 실행 흐름만 여러 개로 쪼개어 가동하는 Multi-Threading 등장. 문제는 Data Race.
    3. 대안으로, 상호 배제Mutual Exclusion 기술이 고안됨. 이 안전 통제 구역을 '임계 구'역이라 하며, 이를 잠그기 위한 동기화 도구(Mutex=Mutual Exclusion Lock, Semaphore, Spinlock)들이 작동. 문제는 deadlock.
- Dirty Page: 유저 버퍼가 다 차거나 플러시되면, 비로소 커널에 시스템 콜을 날려 데이터를 전송합니다. 커널 또한 물리 디스크 대신 자신의 램 영역 일부인 **페이지 캐시(Page Cache)**에 임시 저장
